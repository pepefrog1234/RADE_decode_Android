# v1.6.25 — Recover Icom CAT failures and verify PTT release

Version: `1.6.25-icom-cat-recovery` / `versionCode 10625`.

## Changes

- Send each Icom network PTT request once, removing unsolicited duplicate
  queries/writes that could generate extra CI-V replies. Preserve retransmission
  when the current radio session explicitly requests it.
- Suppress byte-identical duplicate CI-V reply packets and reject packets from
  previous sessions, including stale retransmit requests.
- Recover an Icom session after persistent CAT command rejection, bus errors,
  or empty/invalid frequency and PTT replies. Healthy frequency reads no longer
  hide failed PTT reads, or vice versa.
- Disable Hamlib's status cache and its cache-resetting background publisher
  for the app-owned Icom network daemon. Frequency Set and PTT confirmation
  therefore query the radio instead of accepting a freshly cached write.
- Require a valid OFF readback after an Icom network PTT OFF acknowledgement.
  Missing or ON readback keeps the release warning and background recovery
  active. Repeated unconfirmed OFF attempts also trigger session recovery.
- Add outgoing CI-V frequency/VFO/PTT write details to the Audio Log to help
  trace any further physical dial changes.

## Validation

- `testDebugUnitTest assembleDebug assembleDebugAndroidTest --offline` passes:
  **106 JVM tests, zero failures/errors/skips**, including eight new regression
  tests. Five of the new cases reproduced failures against the previous code.
- Local Hamlib Dummy-daemon testing verifies that both configuration options
  are needed to keep the readback cache disabled.
- Debug and Android instrumentation APKs compile. Physical Android/IC-7300MK2
  testing remains outstanding.

These changes address confirmed control-path defects found while investigating
[issue #10](https://github.com/pepefrog1234/RADE_decode_Android/issues/10). The
available logs do not establish the exact cause of every physical frequency
jump or the reported 48 kHz TX audio interruption; field validation is required.
See the [diagnostic and field-test notes](https://github.com/pepefrog1234/RADE_decode_Android/blob/v1.6.25/docs/diagnostics/icom-cat-recovery-v1.6.25.md).
