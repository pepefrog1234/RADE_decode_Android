# v1.6.3 — V2 の音声異常を修正（FARGAN ウォームアップ）

**v1.6.2 で「クラッシュはしないが V2 のデコード音声がおかしい」問題を修正しました。** V2 をお試しの方はこのバージョンへ更新してください。

## 原因

音声合成器（FARGAN）の初期化処理（fargan_cont）は、**連続した 5 フレーム分**の特徴量バッファを一度に読み込む設計です。従来のコードは 1 フレームずつポインタを渡して 5 回呼んでいました：

- V1 では 1 回の復調で 12 フレーム分の特徴量が届くため、余分な読み込みが偶然バッファ内に収まり、実害なく動いていました
- **V2 は 1 回の復調で 4 フレームしか届かない**ため、5 フレーム分の読み込みがバッファ外にはみ出し、隣のメモリのゴミ値が合成器の再帰状態（リカレントステート）に混入 → 以降のデコード音声がずっと異常になっていました

## 修正と検証

- ウォームアップを正しい設計に変更：最初の 5 フレームを収集してから、正しいレイアウトに詰め直して fargan_cont を 1 回だけ呼ぶ
- V1 も同じ修正の対象です（本来の正しい初期化になるため、受信開始直後の音の立ち上がりがむしろ改善する可能性があります）
- 検証：実音声（16kHz）→ エンコード → V1/V2 送受信 → FARGAN 合成のフル A/B チェックツール（`tools/radecheck/audiocheck`、AddressSanitizer 有効）を追加。修正前は V2 でバッファ外読み込みを検出、修正後は V1・V2 とも正常な音声（入力との包絡相関 V1 0.84 / V2 0.95）を確認

## English summary

Fixes garbled V2 decode audio in v1.6.2. FARGAN's continuation init
(fargan_cont) pre-loads FIVE conditioning frames from one contiguous
NB_FEATURES-stride buffer; the old warmup called it per-frame with a
36-float-stride pointer. On V1 (12 frames per rade_rx batch) the
over-read stayed inside the buffer by luck; on V2 (4 frames per batch)
it read past the features buffer, feeding heap garbage into FARGAN's
recurrent state and garbling all subsequent speech. The warmup now
collects the first five frames, repacks them to the expected stride and
calls fargan_cont once — also the semantically correct init for V1.
Verified with a new full speech A/B harness (tools/radecheck/audiocheck,
ASAN): pre-fix V2 shows the heap-buffer-overflow, post-fix both
waveforms decode clean speech (input-envelope correlation V1 0.84 /
V2 0.95).
