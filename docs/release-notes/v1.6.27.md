# v1.6.27 — Visible TX controls and Icom tuning protection

Version: `1.6.27-controls-tuning-guard` / `versionCode 10627`.

## 修正

- 解出呼號或顯示警告時，TX／停止按鈕保持在畫面底部可見；資訊區可捲動。
- 地圖呼號調整為 12 sp，發射中 14 sp，詳細資料 10 sp，保留粗體與系統字體縮放。
- Icom 網路連線阻擋 Hamlib 自動切換 VFO、探測改頻與還原舊頻率的命令。
  只有使用者按 Set 要求的目前 VFO 頻率可以寫入；許可結束或重新連線後，
  舊 UDP 重傳也無法再次寫入。正常讀取頻率、模式與 PTT 操作保留。

## Changes

- Keep TX and Start/Stop visible when a decoded callsign, warnings or larger
  fonts expand the receiver content. The information area now scrolls.
- Reduce map callsigns to 12 sp (14 sp while transmitting) and details to
  10 sp, preserving bold labels and Android font scaling.
- Protect the selected VFO in Icom network mode from Hamlib's automatic VFO
  probes and frequency restoration. Permit only the exact frequency of an
  active user Set request; reject stale tuning retransmissions after the
  request ends or the session changes.

All **119 JVM tests pass with zero failures/errors/skips**, including the
optional host integration suite. Debug and instrumentation APK builds pass;
the Compose device tests have been compiled but not executed on a device.

The real Hamlib 4.5.5 backend passes host PTY tests with echo enabled/disabled
and equal/different VFO frequencies, including manual Set and repeated PTT.
Physical IC-7300MK2 and phone validation remains necessary. The latest 7177 →
7065 kHz report had no accompanying log, so the exact cause of that occurrence
is not yet confirmed. See [investigation and field checks](https://github.com/pepefrog1234/RADE_decode_Android/blob/v1.6.27/docs/diagnostics/icom-controls-tuning-v1.6.27.md).
