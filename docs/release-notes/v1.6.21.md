# v1.6.21 — CAT reply ordering and RX/audio lifecycle fixes

Version: `1.6.21-cat-rx-lifecycle` / `versionCode 10621`.

Addresses the IC-7300MK2 LTE/VPN report of slow TX/RX switching, intermittent
PTT release failure, silent RX after connecting, frozen waterfall rows and an
unexplained process exit. Physical radio validation is still required.

## Changes

- CAT commands now use complete extended responses with a dedicated reader and
  an ordered transaction queue. Timed-out or cancelled requests retain their
  reply slots until `RPRT` is consumed. A delayed S-meter `0` cannot be mistaken
  for PTT OFF, and an earlier OFF acknowledgement cannot confirm a later OFF
  across an intervening ON.
- Cancelling an ON request no longer waits for a blocking socket read. OFF is
  sent on the same ordered TCP session behind any command already submitted.
  Polls stand down while old replies are outstanding; repeated pending commands
  are coalesced, and the bounded queue reserves capacity for OFF.
- Partial lines survive socket wakeups. A transaction stalled for 15 seconds or
  a malformed reply closes that TCP session and uses the existing local-daemon
  reconnect path. The deadline is measured from command submission, not idle
  socket time.
- RX resumes after the first bounded OFF attempt. If release remains uncertain,
  the PTT warning stays visible, new TX from the Transceiver screen is refused, and background
  OFF/readback recovery continues, including across reconnects. EOO drain and
  the RF tail remain in place.
- Connecting Icom while local RX is already running now switches to network RX
  using the selected output. Reconnecting an existing network RX reattaches its
  callback without recreating that receiver.
- JNI audio calls and engine destruction are serialized and checked against
  their owning `AudioBridge`. In-flight PCM finishes before release; callbacks
  and cancelled pumps from a previous engine cannot operate on a replacement.
  Callback JNI references are copied safely, and TX is stopped before its modem
  is released. Service start/stop transitions are also serialized.
- Spectrum copies include an FFT frame number. Polling an unchanged spectrum
  no longer adds repeated waterfall rows.
- CAT capture now includes audio lifecycle and Java/native fatal-error tags.
  Audio Log remains the preferred capture for crashes because it also includes
  the dedicated crash buffer.

## Validation

- `./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest --offline`:
  successful; **61 unit tests, zero failures/errors/skips**.
- Nine TCP regression cases cover stale meter data, ON cancellation and OFF
  ordering, repeated OFF across ON, coalescing/poll suppression, fragmented
  multi-line replies, mismatched headers, long idle periods, hard transaction
  stalls and reserved OFF queue capacity.
- The production controller was also checked against the installed **Hamlib
  4.7.2 Dummy backend** over loopback: frequency, mode, meters, PTT ON/OFF and
  readback, VFO and power commands worked. The app still uses its bundled
  Hamlib; the host smoke test verifies ERP interoperability, not IC-7300MK2
  backend or LTE behavior.
- `AudioEngineLifecycleTest` compiles into the Android test APK. It exercises
  concurrent PCM feed/release, stale bridge access to a replacement receiver,
  and FFT frame identity without a mic, speaker or RF transmission. **It has
  not run:** no Android device was attached.
- No claim of a confirmed hardware crash fix: the supplied CAT log contains no
  crash stack. The identified native lifetime race has been guarded, but the
  original exit still needs an Audio Log/tombstone to attribute its cause.

## 繁體中文實機測試重點

1. 啟動 App，先以本機模式 RX，再連 Icom；應直接收到網路音訊，不需額外 TX→RX。
2. 測試一般 Disconnect→Connect，再反覆進行短 TX／RX。核對電台實際 PTT
   指示及聲音；正常切換仍包含必要的 EOO／尾音時間。
3. 在 LTE／VPN 延遲或中斷後回 RX，確認「PTT 未確認」會保持顯示，直到收到
   有效 OFF 確認；期間 App 仍持續嘗試解除發射，Transceiver 畫面的新 TX 應被拒絕。
4. 確認音訊停頓時瀑布圖停止新增相同列，恢復後繼續更新。若再次閃退，重開後
   立即匯出 Audio Log，並附上版本、時間與最後一次按鍵動作。
