# v1.5.67 — PureSignal：補正開始直後のクラッシュを修正

決定的なログをありがとうございました。**補正は実際に動き始めていました**（`corr=1`、フィードバックレベルの変化まで記録されています）— クラッシュはその直後の送信終了処理に潜んでいた競合が原因でした。インストールは `app-debug.apk` をご利用ください。

## 原因

WDSP の補正エンジンは、補正係数の切り替え（ランプイン／アウト）を**送信サンプルの流れの中で**完了させる設計です。補正が有効になった状態（`corr=1`）で PTT を離すと、送信サンプルが止まっているのにエンジン内部のスレッドがランプ完了を待ち続け、ロックを保持したまま停止 — 次のキーイングや切断で衝突してクラッシュしていました。補正が始まる前（`corr=0`）は待つものが無いため落ちない — 「これから修正しに行こうという瞬間にクラッシュ」というご観察そのものです。出力（2 W／50 W）に関係なく発生していたのも、純粋なソフトウェアの競合だからです。

## 修正

PTT OFF 時に、補正エンジンへ**約 64 ms ぶんの無音サンプルを別スレッドから流し込み**、ランプアウトを完走させてから解放するようにしました。

## FFTW Wisdom について

ご質問の件：不要です。Thetis／piHPSDR が初回に作る FFTW Wisdom は WDSP の**フィルタ系 FFT** 用で、本アプリが移植した PureSignal の校正計算（calcc）と補正適用（iqc）は **FFT を一切使いません**。今回のクラッシュとも無関係です。

## テストのお願い

前回と同じ手順で、今度は `corr=1` になった後も**そのまま送信を続け／何度か送受切替**してみてください。`ps=[state=8 corr=1]`（補正適用が定常化）まで進むか、スペクトラムの IMD 改善が見えるかが次の確認ポイントです。なお前回ログで −12 dB のフィードバックゲインは適正（ovf=0・fblvl≈40 で安定）と確認できています。

## English summary

Fixes the reproducible crash right after PureSignal's correction
engaged (`corr=1`): WDSP completes coefficient ramp-in/out only through
continued TX-sample flow, so releasing PTT with correction active left
the engine's control thread parked in a lock-holding busy-wait — the
next key/teardown crashed. PTT-off now drains ~64 ms of zero samples
through psApply on a worker thread to complete the ramp before release.
Output power was irrelevant (pure software race). FFTW Wisdom (asked
about) is not needed: the vendored calcc/iqc use no FFT. The previous
log also validated the −12 dB feedback gain (ovf=0, stable fblvl≈40).
