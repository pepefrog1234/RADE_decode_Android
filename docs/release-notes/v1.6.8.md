# v1.6.8 — Icom Wi-Fi：トークン削除を確実化（再接続 NG の追加修正）/ Reliable token removal

v1.6.7 のテストで判明した「**ユーザー名/パスワードを変えると1回だけ接続できるが、同じユーザーでは再接続できない**」問題の修正版です。インストールは `app-debug.apk` をご利用ください。

## 原因（日本語）

IC-705 は**ユーザーごとにトークン（ログイン札）**を保持します。アプリは切断時にトークン削除（ログアウト通知）を**1回だけ**送信してすぐソケットを閉じていたため、この UDP パケットが届かないことが多く、無線機側に古いトークンが残っていました。トークンが残っている間、**同じユーザーの新しいログインは無視されます**（別ユーザーなら新しいトークン枠で接続できる——ご報告の挙動そのものです）。

## 修正内容

切断処理を確実化しました：シリアルのクローズを2回、**トークン削除を3回**送信し、パケットが確実に送出・処理されるのを待ってから（120ms）各ストリームを閉じます。

## 更新後のお願い（重要）

**最初に IC-705 の電源を一度入れ直してください。** 旧バージョンが残した古いトークンはアプリからは削除できません（数分待っても自然消滅します）。その後は、同じユーザー名/パスワードのまま「接続 → 切断 → 再接続」を何度繰り返しても毎回つながるはずです。NG が出る場合は、何回目の接続で・どのエラー文言が出たかをお知らせください。

## In English

Follow-up to v1.6.7: connects succeeded only once per set of credentials because the token-removal (logout) packet was sent exactly once, fire-and-forget, right before the sockets closed — routinely lost, so the radio kept the user's stale token and ignored the next login. v1.6.8 sends the serial close twice and the token removal three times, then waits 120 ms before tearing the streams down. **After updating, power-cycle the radio once** to clear any token left by an older version; from then on repeated connect/disconnect cycles should work every time.
