# v1.5.57 — HL2 (LAN)：送信の安定化と診断ログ

HL-2 LAN 接続のテスト、本当にありがとうございます！「受信は完璧」とのご報告で、発見（ホスト空欄のブロードキャスト）・プロトコル・I/Q 復調・側波帯の向きまで、実機で一気に検証できました。残るは送信のみです。インストールは `app-debug.apk` をご利用ください。

## まずご確認いただきたいこと：「送信ドライブ」スライダー

無線機画面（HL2 (LAN) モード）の「**送信ドライブ / TX drive**」スライダーをご確認ください。**この値が 0（または極小）だと、リレーは動作するのに RF 出力はゼロ**になります — ご報告の症状（リレー動作・変調なし）と完全に一致します。設定はスマホごとに保存されるため、ご友人の端末（初期値 128）では送信できて、お使いの端末では出ない、という違いも説明できます。**128 前後にして再度お試しください。**

## ご質問への回答

- **ホストは空欄のままで良いですか？** → はい。空欄＝ブロードキャスト自動発見で、今回まさにそれで接続できています。
- **送信出力デバイスは built-in speaker で良いですか？** → HL2 (LAN) モードでは**送信出力デバイス設定は一切使われません**（変調は LAN 経由で無線機へ送られます）。どの値でも影響ありません。RX 入力デバイス設定も同様に不使用です。

## 本バージョンの修正

1. **送信 I/Q の送出を自己クロック化。** これまで送信中の EP2 パケットは「EP6（受信ストリーム）を受け取るたびに 1:1 で返送」する方式でした。ゲートウェアによっては送信中に受信ストリームを止めるため、その場合の予備送出はタイマー精度の粗い端末で乱れる可能性がありました。本バージョンから **MOX 中は EP6 に依存せず、絶対デッドラインで正確に 48 kHz を自己クロック送出**します（40 ms 以上遅れたらバースト再送ではなく再同期）。
2. **送信ヘルスログを追加。** 送信中 1 秒ごとに `TX health: ep2=毎秒パケット数 iqRing=バッファ iqUnderrun=不足サンプル drive=値 freq=周波数` を記録します。これで「ドライブが 0」「I/Q が生成されていない」「パケットが無線機に届いていない」を一目で切り分けられます。
3. **アプリ内ログ取得に HermesNet を追加。** 前回のキャプチャに HL2 プロトコル層の行が含まれていなかったのは、取得フィルタの漏れでした。修正済みです。

## もし送信ドライブを上げても出力が出ない場合

1. v1.5.57 に更新 → HL2 接続 → 送信を数秒
2. 設定 → 診断 → **Capture audio log** → コピー
3. その内容（`HermesNet` の `TX health:` 行を含みます）を Issue に貼ってください

これで原因を確定できます。重ねて、貴重なテストとご報告に感謝します！

## English summary

HL2 (LAN) hardware test results: **RX works perfectly** (discovery,
protocol 1, I/Q demod and sideband orientation all confirmed on real
hardware). TX keyed the relay but produced no RF on the reporter's phone
while the same APK transmitted fine from a friend's phone.

- Most likely cause: the **TX drive slider at 0** (per-device pref;
  fresh installs default to 128) — an HL2 with drive 0 keys the relay
  but outputs zero RF. Please check the slider first.
- Robustness fix: EP2 is now **self-clocked at 48 kHz during MOX**
  (absolute deadlines, resync instead of catch-up bursts) instead of
  being paced 1:1 by the received EP6 stream — TX no longer depends on
  whether the gateware keeps streaming RX while transmitting.
- New per-second `TX health` log (packets/s, I/Q ring level, underruns,
  drive, frequency) and the `HermesNet` tag is now included in the
  in-app log capture, so one capture pinpoints any remaining TX issue.
- The TX-output / RX-input device settings are **not used** in HL2 (LAN)
  mode; audio rides the network. Blank Host = broadcast auto-discovery
  (working as designed).
