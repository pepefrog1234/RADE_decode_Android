# v1.5.72 — PureSignal：ロック後の継続オートキャリブレーション（Thetis 方式）

「数 dB 程度の改善」のご報告ありがとうございます。補正ループが初めて実際に働きました（前回ログ：外部フィードバック優勢で +10dB ロック、実測モデル AM/AM 1.98dB / AM/PM 約5°）。

数 dB と Windows の 10dB+ の差は、構造的な理由によるものです：**Thetis / piHPSDR は連続オートキャリブレーション**（約 1 秒ごとに補正済み信号で再計算し、係数をシームレスに更新）で残差を繰り返し追い込みますが、本アプリはこれまで **PTT ごとに 1 回だけ**校正していました（過去の不具合調査のための安全設計）。1 回きりの校正で得られるのは一次補正のみで、「数 dB」はその典型値です。

## v1.5.72 の変更

- **ロック後、WDSP の automode（連続再校正）を有効化** — Thetis と同じ動作。約 1 秒ごとに補正済みリファレンスで再計算し、精度を繰り返し改善、温度ドリフトにも追従します
  - ロック直後の 1〜2 秒だけ、再学習のため補正が一瞬外れます（その後は連続適用）
  - ロック中に ADC overflow を検出した場合は、その送信の間は精修を凍結し、確定済み補正を保持します（`LOCKED_STATIC`）
- **クロストーク警告**：ロック時の feedback gain が +15dB 以上の場合、「外部サンプラーではなく内部クロストークを聴いている可能性が高い」旨を警告ログに出力（今回の問題を今後は一目で検出できます）
- **精修中のモデルを約 12 秒ごとにログ出力**（`PS model:` 行）— 収束の様子がログで追えます
- **接続時にアプリのバージョンをログに出力** — ログがどのビルドか常に判別可能に

## テストのお願い

1. 現在のアッテネーター設定のまま、PS ON で **30 秒以上**送信（連続精修が数サイクル回る時間）
2. PS ON/OFF のスペクトラム比較 — 前回より深い改善（Windows に近い値）を期待しています
3. 可能なら、フィードバックのアッテネーターをさらに約 6dB 減らしてもう一度（ロックが +4dB 前後になり、クロストークの影響がさらに減って補正精度が上がります。overflow 保護があるので安全です）
4. ログをお送りください — `PS model:` 行の AM/AM・AM/PM が精修とともに安定していく様子と、ショルダーの改善量を突き合わせます

## English summary

The tester finally observed a few dB of on-air IMD improvement after fixing
the feedback-level problem (external sampler now dominates the TRX-relay
crosstalk; locked at +10 dB with a real measured model: AM/AM 1.98 dB,
AM/PM ≈5°). The gap to the 10 dB+ seen with Windows software is structural:
Thetis/piHPSDR run continuous auto-calibration, while this app performed a
single one-shot per PTT (a safety choice from the earlier debugging phase) —
a single shot only yields the first-order correction. v1.5.72 enables WDSP
automode after the controller locks (seamless ~1 Hz coefficient refinement,
thermal tracking; frozen to LOCKED_STATIC on ADC overflow), warns when the
lock gain ≥ +15 dB (crosstalk-dominated feedback detection), logs the fitted
model every ~12 s during refinement, and prints the app version at connect.
