# v1.6.20 — Reliable Icom logout and isolated reconnect attempts

Test build for the IC-7300MK2 / IC-705 reports of reconnect failures and PTT remaining keyed when the network session stops during TX.

## English

The v1.6.19 field log confirms that the watchdog and automatic reconnect work, but two sessions still stopped delivering CI-V and audio during TX. In the first event, PTT-off was acknowledged only after reconnecting about a minute later. Both data stoppages occurred roughly 60 seconds after the preceding failed connection attempt ended. That timing suggests stale session cleanup may affect a later connection; it does not prove the radio's internal cause.

This build fixes concrete problems in the client's logout and connection lifecycle:

- Logout now uses a tracked deauthentication packet with a valid sequence number and retransmit-buffer entry. The two proactive repeats reuse exactly the same packet.
- Readers, idles and ping replies remain available for 500 ms before stream goodbye, allowing the radio to request a lost logout packet. Normal audio, CI-V and re-auth traffic stops; retransmit requests cannot replay old PTT-on or re-auth packets during logout.
- Only a matching successful logout reply clears the saved token. An unacknowledged token receives the existing one-shot cleanup before the next login; that cleanup preserves the first login's inner sequence of zero.
- Each full connection attempt gets a fresh login request ID. Delayed login replies from a previous attempt are ignored. Grants can still update session IDs and tokens, as required by the reference implementations.
- Teardown callbacks are bound to the session that created them. A queued callback from an old connection cannot close a newer connection. Radio-triggered teardown during initial stream setup remains retryable; operator cancellation still stops the request.
- CAT logs now include logout sequencing/acknowledgement and authentication response fields. Passwords and full tokens are not logged.

The existing watchdog and background PTT-off recovery remain in place. This is a candidate fix for the reported hardware behavior, not a claim of confirmed resolution.

這次修正仍須 IC-705／IC-7300MK2 實機確認，尚不能宣稱已根治。

## Hardware validation

Use the app version banner `1.6.20-session-logout` to identify this build. On each radio, test Disconnect → Connect with a short delay (0–5 seconds), then with 20- and 60-second delays. After each successful reconnect, receive for at least 2–3 minutes and perform several short TX/RX cycles. Check actual PTT release and RX audio, not just the green connection indicator. Capture the CAT log immediately if a failure occurs, including the `logout sent`, `logout grace ended`, `control 0x40`, and reconnect lines.
