# v1.5.58 — HL2 (LAN)：Wi-Fi 省電対策と「電波が出ない」原因の確定用診断

詳細なログをありがとうございます。おかげで大きく絞り込めました。インストールは `app-debug.apk` をご利用ください。

## ログから分かったこと

お送りいただいた `TX health` の記録では、**アプリ側は完全に正常**でした：

- `ep2=381〜382/s` — 送出パケットレートは理論値どおり（48000 ÷ 126）
- `iqRing` は常にデータあり・`underrun=0`（先頭1秒のみ起動待ちで正常）
- `drive=255`、周波数・MOX も正しく送出

それでも RF が出ない。そして「HL-2→スマホは届くのに、スマホ→HL-2 は一方通行」というご観察 — これは**スマホの Wi-Fi 省電機能が上り方向の UDP を絞っている**ときの典型的な症状です。送信 I/Q は上り約 3 Mbit/s を連続で必要とします。上りが間引かれると、（わずかに届いたパケットで）リレーはキーイングされるのに、HL-2 の送信 FIFO が枯れて変調が出ません。受信（下り）は影響を受けないため「一方通行」に見えます。ご友人のスマホで送信できたのは、Wi-Fi チップ／省電ポリシーの違いで説明がつきます。

## 本バージョンの対策

1. **Wi-Fi パフォーマンスロック** — HL2 接続中はスマホの Wi-Fi 省電を抑止します（Android 10 以降は低遅延モード）。今回の本命の対策です。
2. **DSCP EF マーキング** — I/Q ストリームを音声クラスの優先度で送出するよう Wi-Fi ドライバ／AP に指示します（ベストエフォート）。
3. **無線機からの状態報告をログに追加** — HL-2 が返してくる**進行方向電力（fwd）**・反射電力・PA 電流・温度・EP6 パケット欠落数を `TX health` 行に追記しました。次回のログで原因が確定します：
   - `fwd` が 0 のまま＆パケット欠落が多い → ネットワーク（上り）の問題
   - `fwd` が 0 だがパケットは全部届いている → 無線機側（LPF フィルタボード等）
   - `fwd` に値が出る → 実は電波は出ている
4. **切断ボタンのバグ修正** — Disconnect を押したときの停止コマンドがメインスレッド制限で送信されておらず（ログに例外が出ていました）、無線機側がしばらくストリームを続けていました。修正済みです。

## お願い

1. v1.5.58 に更新して、これまでと同じように送信をお試しください
2. **改善しない場合**は、送信数秒 → 設定 → 診断 → Capture audio log で再度ログをお送りください（`TX health` 行の `| radio: fwd=…` の値が決め手になります）
3. 可能でしたら、スマホが 2.4 GHz と 5 GHz のどちらで接続しているか、また同じスマホの位置から SparkSDR 等の PC ソフトで送信できるかも教えていただけると助かります

## English summary

The tester's v1.5.57 log proves the app side is perfect during TX
(ep2=381–382/s exactly, healthy I/Q ring, zero underruns, drive 255) yet
no RF is produced, and RX keeps working — a one-way upstream failure.
That signature points at phone Wi-Fi power save throttling the sustained
~3 Mbit/s UDP *upstream* the TX I/Q needs: the relay keys off the few
frames that arrive, but the radio's TX FIFO starves.

- The app now holds a **Wi-Fi performance lock** (low-latency mode on
  Android 10+) while connected to an HL2, and marks the I/Q socket
  **DSCP EF** (WMM voice class).
- The per-second `TX health` log now includes the **radio-reported
  forward/reverse power, PA current, temperature and EP6 packet-loss
  count**, which will definitively separate "packets not arriving" from
  "radio not emitting" if the problem persists.
- Fixed: the Disconnect button's stop command was blocked by Android's
  main-thread network restriction (exception visible in the tester's
  log), leaving the radio streaming until its watchdog fired.

Also included: the README (all four languages) now documents the HL2
(LAN) mode, Bluetooth / LE Audio output, TX-mic selection and the
in-app diagnostics.
