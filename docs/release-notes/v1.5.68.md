# v1.5.68 — PureSignal：送信中に補正が崩れる問題を修正

`log4`／`log5` と、「PTT OFF 後ではなく、送信状態のまま 1～10 秒で発生する」という正確なご説明をありがとうございました。送られたログにはプロセス異常終了のスタックは含まれていませんでしたが、PureSignal の最初の補正が入った直後に送信信号の平均レベルが約 10 dB 崩れ、その後は停止ボタンによる通常の TX 停止／PTT OFF の順序になっていることを確認できました。

## 原因

Hermes-Lite 2 の PureSignal 用 2 受信ストリームの意味を逆に解釈していました。

- **RX1**：物理 ADC に入る PA 出力フィードバック
- **RX2**：HL2 FPGA 内部の TX DAC 参照信号

従来版は RX2 を PA フィードバックだと誤認し、さらにスマートフォン側で推定した遅延付き TX 参照と比較していました。そのため PA ではなく TX 参照経路そのものを誤って逆補正し、`corr=1` になった瞬間に送信波形が崩れていました。ログで RX2 peak が周波数に関係なく約 −12.4 dBFS で安定していたことも、RX2 が HL2 の内部 DAC 参照であることと整合します。

## 修正

- HL2／piHPSDR と同じ接続に変更：**TX reference = RX2、PA feedback = RX1**
- FPGA で同時刻に生成された RX1／RX2 をそのまま 1024 sample のペアとして WDSP に入力
- 誤ったスマートフォン側 TX reference ring、TX FIFO backlog／40 ms 遅延推定を削除
- HL2 Protocol 1 の TX DAC reference peak `0.24` を WDSP の hardware peak に設定
- アプリ側の固定デジタル送信スケール `0.8` を RX2 だけ `1.25` 倍で戻してから校正（piHPSDR の drive inverse と同じ扱い）
- 通常の PTT OFF では有効な補正係数を保持し、MOX だけを OFF に変更
- v1.5.67 の `psApply` だけを流す非同期 drain を削除（`psFeed` が無いため ramp-out を開始できず、今回の送信中不具合の経路でもありませんでした）

## 追加の安全性・診断改善

- WDSP の非同期校正 worker が終了する前に CALCC／IQC を解放し得た native use-after-free を修正
- TX 開始時のデバイス再検索が、一時的な `AudioBridge` を作って Service の使用中 native AudioEngine を置き換える競合を修正
- 診断ログに `PureSignalPS`、`AndroidRuntime`、`libc`、`DEBUG` と Android の crash buffer を追加（端末権限で読める範囲の best effort）
- TX health の表示を `rx1Fb`（PA feedback）／`rx2Ref`（DAC reference）に改名
- RX1／RX2 の順序を固定する単体テストを追加

## 再テストのお願い

前回と同じ HL2 (LAN)／PA ON／PureSignal ON で、少なくとも 30 秒の送信と数回の送受切替をお試しください。新しいログでは `corr=1` の後も `rx2Ref` と送信電力が突然約 10 dB 落ちないことをご確認ください。万一アプリ自体が終了し、Capture audio log に fatal stack が出ない場合は、完全な `adb logcat -b all` または Android bugreport も併せてお送りください。

## English summary

Fixes the active-TX PureSignal collapse reported in issues #17/#18. HL2
gateware exposes RX1 as the physical ADC/PA feedback and RX2 as its internal
TX-DAC reference; v1.5.66–1.5.67 treated RX2 as PA feedback and calibrated it
against a separately delayed phone-side reference. The first accepted bogus
correction (`corr=1`) therefore reduced the transmitted waveform RMS by about
10 dB. v1.5.68 feeds the hardware-aligned pair in WDSP order (RX2 TX reference
first, RX1 PA feedback second), uses the HL2 Protocol-1 hardware peak of 0.24,
reverses the app's fixed 0.8 digital drive scale on RX2, and removes the
incorrect software reference ring/delay. It also preserves
correction across normal PTT cycles, waits for detached WDSP calibration
workers before freeing their engine, fixes device enumeration replacing the
live native AudioEngine, expands crash capture, and adds an RX mapping unit test.
