# v1.6.29 — Icom CAT recovery and background RX reconnect

Addresses the remaining v1.6.28 reports in [issue #10](https://github.com/pepefrog1234/RADE_decode_Android/issues/10), including failed Set/PTT commands, RX interruptions and a background reconnect crash.

Install the signed `app-release.apk` attached to this release.

## English

- Validate CI-V replies before handing them to Hamlib. Supply a consistent local echo and discard physical echoes, mismatched replies and completed-command retransmissions. Delayed frequency reads cannot acknowledge a new frequency write.
- Acknowledge only virtual VFO A/B selections. Blocked frequency probes return failure; a user Set must still have an exact, expiring frequency permit.
- Detect persistent failure of individual essential CAT commands, even when other reads still work. Defer repair during active TX, while allowing pending PTT-OFF recovery after audio TX ends.
- Restart a stalled CAT daemon on the existing PTY first, retaining healthy network audio. Verify fresh radio frequency and PTT readback and use a full network reconnect only if local repair fails.
- Resume RX after network loss through the existing foreground service. Automatic recovery no longer starts a new foreground service from the background; Stop revokes automatic audio recovery.

These changes address reproducible software failures. IC-7300MK2 LTE/VPN and Android lock-screen operation still need hardware testing. CI-V has no transaction ID, so identical late replies cannot always be distinguished; network outages themselves can still interrupt audio.

## 繁體中文

- 修正 CI-V echo 與回覆混淆，檢查命令、位址與子命令，避免舊讀頻回覆被誤當成新寫頻成功。
- 僅虛擬 VFO A/B 選擇回 ACK；被擋下的寫頻不再假報成功，仍須明確 Set 授權。
- 核心 CAT 指令持續失敗時自動修復；其他讀取成功不再掩蓋 PTT 失效。實際發射中延後修復，返回 RX 後允許處理未確認的 OFF。
- 優先只重啟 rigctld 並讀回確認，保留正常的 UDP 與音訊；失敗才完整重連。
- 修正背景重連觸發前景服務限制的崩潰，沿用既有服務；Stop 會撤銷自動恢復音訊。

尚須 IC-7300MK2、LTE/VPN 與 Android 鎖屏實機驗證；不保證消除網路本身的停流。
