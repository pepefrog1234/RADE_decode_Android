# v1.5.59 — HL2 (LAN)：送信の途切れ（不安定）対策

「LAN で送信は動くが不安定」とのご報告を受けての改善版です。インストールは `app-debug.apk` をご利用ください。

## 原因の見立て

2つの取りこぼしがありました。どちらも「送信は出るが途切れる・不安定」という症状に直結します：

1. **無線機側の送信バッファが既定のままだった。** HL-2 のゲートウェアは、ホストが指定しない限り送信 FIFO のプライミングを **約 10 ms** しか取りません。スマホ側のスケジューリングは（GC・画面操作・省電などで）10 ms を超える揺らぎが普通に起きるため、その度に無線機側のバッファが枯れて RF が途切れていました。PC 用ソフト（Quisk 等）はこの値を大きく設定しています — 本アプリも今回から **40 ms** を設定するようにしました（プロトコル addr 0x17）。

2. **送出タイミングの精度。** パケット送出（2.625 ms 間隔）をコルーチンで行っていましたが、負荷がかかると数 ms〜数十 ms の揺らぎが出ます。**音声優先度の専用スレッド + 高精度スリープ**に変更し、揺らぎを大幅に抑えました。また一時的な停滞の後は（バッファが深くなったので）**取りこぼした分を正確に補送**して途切れを自己修復します（100 ms を超える停滞のみ再同期）。

## もし改善しきらない場合のヒント

- 送信中の **RF 回り込み**が Wi-Fi を乱すことがあります（HL-2 + Wi-Fi ホストの定番問題です）。アンテナ／同軸がスマホや Wi-Fi ルーターに近い場合、フェライトコアの追加・距離の確保・**5 GHz Wi-Fi への変更**が効きます。症状がバンドや出力に依存するならこれが濃厚です。
- 再度ログをいただければ切り分けできます：送信数秒 → 設定 → 診断 → Capture audio log。`TX health` 行の `| radio: ep6=…/s gaps=… fwd=…` で、パケット欠落（ネットワーク）か、電力計の値（無線機側）かが分かります。

いつもテストとご報告をありがとうございます。おかげで HL2 対応が一歩ずつ実用になっています。

## English summary

Follow-up to "LAN TX works but is unstable":

1. **The radio-side TX FIFO was left at its gateware default (~10 ms
   priming).** Any phone-side scheduling hiccup longer than that starved
   the HL2's FIFO mid-over — choppy RF. The app now sets protocol
   addr 0x17 with a **40 ms TX buffer latency** (and 4 ms PTT hang),
   matching common PC hosts.
2. **Tighter packet pacing.** The EP2 pacer moved from a coroutine to a
   dedicated audio-priority thread with high-resolution sleeps; after a
   transient stall it now **catches up exactly the deficit** (safe with
   the deeper radio FIFO — no overflow) and only resyncs past 100 ms.

If instability persists, RF ingress into Wi-Fi is the usual remaining
suspect (ferrites / distance / 5 GHz Wi-Fi help), and another in-app log
capture (`TX health` → `gaps`, `fwd`) will separate network loss from
radio-side issues.
