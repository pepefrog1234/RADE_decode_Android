# v1.6.36 — Rig control closed to the network; Hamlib 4.7.2

The CAT daemon inside the app (Hamlib `rigctld`) accepted connections from every
network the phone was on, without a login. From this version it accepts them from
the phone itself only. The daemon is also rebuilt from source: Hamlib 4.7.2 in
place of 4.5.5, with seven patches and stack protection.

This is the first release since v1.6.31. It also contains v1.6.32 (RADE modem
update) and v1.6.33 (PTT confirmed from the radio,
[issue #33](https://github.com/pepefrog1234/RADE_decode_Android/issues/33)),
which were not published as releases.

Install the signed **`app-release.apk`** attached to this release.

## English

**Security**

- While the app was connected to a rig through its built-in CAT daemon (USB CAT
  cable, Icom Wi-Fi, or a TCP profile that uses a Hamlib model), any device on
  the same Wi-Fi, hotspot or VPN could connect to the phone's port 4532 and
  control the radio: retune it, send it raw CAT commands, key the transmitter.
  The daemon has no login. It now listens on the phone's own address
  (127.0.0.1) only.
- If you let another program on your network control the rig through the phone's
  port 4532, that no longer works.
- The bundled Hamlib is 4.7.2 (was 4.5.5). It has the fixes for CVE-2026-54634
  and GHSA-f72v-7gmh-m9mj. In 4.5.5 a long command name or argument from a
  client also overwrote the daemon's stack.
- Five more memory errors that are still in 4.7.2 are patched in this build, and
  the daemon is compiled with stack protection. If Hamlib still writes past a
  buffer somewhere, the daemon now stops and the Rig tab shows
  `rigctld: DIED: killed by SIGABRT (6)`. Please report the rig model if you see
  that.
- Not changed: other apps on the same phone can still connect to the daemon.

**Rig control**

- Sixteen more models in the Rig tab: QRP Labs QMX, Icom IC-7300MK2, IC-7760 and
  IC-905, Xiegu X6200, Yaesu FTX-1 and FTDX-9000 Old, Thetis, SDR Console,
  (tr)uSDX, Hamgeek uSDX, BG2FX FX4 series, Codan 2110, CommRadio CTX-10,
  Guohetec PMR-171 and Q900. They are at the end of the list; the manufacturer
  filter and the search find them. Your saved selection is unchanged.
- QRP Labs radios: after you set a frequency in the app, the radio is switched
  to LSB below 10 MHz and to USB above. Until now the app asked for a data mode
  these radios do not have, and nothing happened. Hamlib 4.7.2 would turn that
  request into the QMX's FSK (Digi) mode, which cannot transmit a RADE signal.
- There are two entries for the QMX now. "QMX/QDX" is the one earlier versions
  had; "QMX" is Hamlib's newer model for it. Neither has been tried on a radio
  with this Hamlib version. Stay with "QMX/QDX" unless it fails.
- Icom Wi-Fi: Hamlib 4.7.2 connects to the radio with read commands only. 4.5.5
  switched VFOs and retuned by 100 Hz to find out which VFO was selected, and
  the app has intercepted those writes since v1.6.27. The interception stays.

**From v1.6.32 and v1.6.33**

- RADE modem updated to upstream rade_c `be66f39`. The V1 signal on the air is
  unchanged. The experimental V2 mode decodes at lower audio levels and with a
  sound-card clock offset, and no longer crashes at the end of a received over.
  See the [v1.6.32 notes](https://github.com/pepefrog1234/RADE_decode_Android/blob/v1.6.36/docs/release-notes/v1.6.32.md).
- After a key-on the app reads the radio's own transmit status and repeats the
  key-on, up to twice, while the radio still reports receive. A failed S-meter
  read no longer holds up the commands behind it. This is the first published
  version with that change. See the
  [v1.6.33 notes](https://github.com/pepefrog1234/RADE_decode_Android/blob/v1.6.36/docs/release-notes/v1.6.33.md);
  where they say Hamlib 4.5.5, the same was measured again with 4.7.2.

## 繁體中文

**安全性**

- App 透過內建的 CAT 服務程式連接電台時（USB CAT 線、Icom Wi-Fi，或使用 Hamlib
  機型的 TCP 設定），同一個 Wi-Fi、熱點或 VPN 上的任何裝置都能連到手機的 4532
  埠控制電台：改頻率、送原始 CAT 指令、按下發射。這個服務程式沒有登入機制。
  現在它只接受手機本機（127.0.0.1）的連線。
- 如果你原本讓網路上的其他程式經由手機的 4532 埠控制電台，這個用法不再可行。
- 內建的 Hamlib 由 4.5.5 換成 4.7.2，已包含 CVE-2026-54634 與
  GHSA-f72v-7gmh-m9mj 的修正。4.5.5 另有一個問題：連線端送來過長的指令名稱或
  參數，會覆寫服務程式的堆疊。
- 4.7.2 仍有的五個記憶體錯誤已在這次建置中修補，服務程式也改用堆疊保護編譯。
  如果 Hamlib 還有其他地方寫出緩衝區，服務程式會直接結束，Rig 分頁顯示
  `rigctld: DIED: killed by SIGABRT (6)`。看到這個訊息請回報電台型號。
- 沒有改變的是：同一支手機上的其他 app 仍然連得到這個服務程式。

**電台控制**

- Rig 分頁新增 16 個機型：QRP Labs QMX、Icom IC-7300MK2／IC-7760／IC-905、
  Xiegu X6200、Yaesu FTX-1／FTDX-9000 Old、Thetis、SDR Console、(tr)uSDX、
  Hamgeek uSDX、BG2FX FX4 系列、Codan 2110、CommRadio CTX-10、Guohetec PMR-171／
  Q900。它們排在清單最後，用廠牌篩選或搜尋都找得到；你已儲存的機型選擇不受影響。
- QRP Labs 電台：在 app 設定頻率後，電台會切到 LSB（10 MHz 以下）或 USB。以往
  app 要求的是這些電台沒有的數據模式，所以什麼都不會發生；換成 Hamlib 4.7.2
  後，同樣的要求會變成 QMX 的 FSK（Digi）模式，而該模式無法發射 RADE 訊號。
- QMX 現在有兩個項目。「QMX/QDX」是先前版本就有的；「QMX」是 Hamlib 新增的專用
  機型。兩者都還沒有在實機上搭配這版 Hamlib 測試過；除非「QMX/QDX」不能用，
  否則請維持原選擇。
- Icom Wi-Fi：Hamlib 4.7.2 連線時只送讀取指令。4.5.5 會切換 VFO 並把頻率移動
  100 Hz 來判斷目前的 VFO，app 從 v1.6.27 起一直在攔截這些寫入。攔截機制保留。

**來自 v1.6.32 與 v1.6.33**

- RADE 數據機更新到上游 rade_c `be66f39`。V1 的空中訊號不變；實驗性的 V2 可在
  更低的音訊電平與音效卡時脈偏差下解碼，接收結束時也不再當機。詳見
  [v1.6.32 說明](https://github.com/pepefrog1234/RADE_decode_Android/blob/v1.6.36/docs/release-notes/v1.6.32.md)。
- 送出 key-on 後，app 會讀取電台自己的收發狀態；電台仍回報接收時重送 key-on，
  最多兩次。S 表讀取失敗不再拖住排在後面的指令。這是第一個包含此修改的正式
  發佈版本。詳見
  [v1.6.33 說明](https://github.com/pepefrog1234/RADE_decode_Android/blob/v1.6.36/docs/release-notes/v1.6.33.md)；
  其中提到 Hamlib 4.5.5 的行為，已用 4.7.2 重新量測，結果相同。

## 日本語

**セキュリティ**

- アプリが内蔵の CAT デーモンで無線機に接続している間（USB CAT ケーブル、Icom
  Wi-Fi、Hamlib の機種を使う TCP 設定）、同じ Wi-Fi・テザリング・VPN 上のどの
  機器からも、スマートフォンのポート 4532 に接続して無線機を操作できました。
  周波数の変更、CAT コマンドの直接送信、送信の開始が可能で、ログインは
  ありません。本版から、デーモンはスマートフォン自身（127.0.0.1）からの接続
  だけを受け付けます。
- ネットワーク上の別のプログラムから、スマートフォンのポート 4532 経由で無線機を
  操作していた場合、その使い方はできなくなります。
- 同梱の Hamlib を 4.5.5 から 4.7.2 に更新しました。CVE-2026-54634 と
  GHSA-f72v-7gmh-m9mj の修正を含みます。4.5.5 では、接続元が長いコマンド名や
  引数を送るとデーモンのスタックが上書きされる問題もありました。
- 4.7.2 に残っているメモリエラー 5 件を修正し、デーモンをスタック保護付きで
  ビルドしました。Hamlib がまだどこかでバッファの外に書き込む場合、デーモンは
  停止し、Rig タブに `rigctld: DIED: killed by SIGABRT (6)` と表示されます。
  この表示が出たら機種をお知らせください。
- 変わっていない点：同じスマートフォン上の他のアプリからは、引き続きデーモンに
  接続できます。

**リグコントロール**

- Rig タブに 16 機種を追加しました：QRP Labs QMX、Icom IC-7300MK2／IC-7760／
  IC-905、Xiegu X6200、Yaesu FTX-1／FTDX-9000 Old、Thetis、SDR Console、
  (tr)uSDX、Hamgeek uSDX、BG2FX FX4 シリーズ、Codan 2110、CommRadio CTX-10、
  Guohetec PMR-171／Q900。リストの末尾にあり、メーカーの絞り込みや検索で
  見つかります。保存済みの機種選択は変わりません。
- QRP Labs の無線機：アプリで周波数を設定すると、10 MHz 未満では LSB、それ以上
  では USB に切り替えます。これまでは、これらの無線機にないデータモードを要求
  していたため、何も起きませんでした。Hamlib 4.7.2 では同じ要求が QMX の FSK
  （Digi）モードになり、このモードでは RADE 信号を送信できません。
- QMX の項目が 2 つになりました。「QMX/QDX」は従来からの項目、「QMX」は Hamlib
  が新たに用意した専用モデルです。どちらも、この Hamlib との組み合わせで実機
  確認はできていません。「QMX/QDX」で動作しない場合を除き、そのままお使い
  ください。
- Icom Wi-Fi：Hamlib 4.7.2 は読み取りコマンドだけで無線機に接続します。4.5.5 は
  選択中の VFO を調べるために VFO を切り替え、周波数を 100 Hz 動かしていました。
  アプリは v1.6.27 からこの書き込みを遮断しており、遮断の仕組みは残しています。

**v1.6.32 と v1.6.33 の内容**

- RADE モデムを上流 rade_c `be66f39` に更新しました。V1 の電波上の信号は
  変わりません。実験的な V2 は、より低い音声レベルやサウンドカードのクロック
  誤差があっても復調でき、受信終了時にクラッシュしなくなりました。
  [v1.6.32 の説明](https://github.com/pepefrog1234/RADE_decode_Android/blob/v1.6.36/docs/release-notes/v1.6.32.md)
  をご覧ください。
- key-on のあと、無線機自身の送受信状態を読み取り、受信のままなら key-on を
  再送します（最大 2 回）。S メーターの読み取りに失敗しても、後続のコマンドが
  待たされなくなりました。この修正を含む最初の公開版です。
  [v1.6.33 の説明](https://github.com/pepefrog1234/RADE_decode_Android/blob/v1.6.36/docs/release-notes/v1.6.33.md)
  をご覧ください。Hamlib 4.5.5 について書かれている動作は、4.7.2 でも測定し直し、
  同じ結果でした。

## Validation and limits

- With `RADE_TEST_RIGCTLD` set to a host build of the same patched Hamlib 4.7.2
  sources: 201 tests passed, none skipped. Eighteen of them run the app's own
  code against the real daemon: it answers on loopback and on no other address
  of the machine; PTT and modes against a QMX-style radio on a PTY, for both QMX
  models; nine Icom tuning scenarios; and every model of the Rig tab against the
  daemon's own model list.
- Without it, as in CI: 183 passed, those 18 skipped.
- The same 18 also pass against an AddressSanitizer build of the daemon, with no
  report.
- Every rigctld command was sent with hostile arguments to AddressSanitizer
  builds (6860 cases): 4 crash on the unpatched 4.7.2, none on the patched one.
  Of the five memory errors, four can be reached by a client of the daemon and
  one by a radio's answer.
- The arm64 daemon in the APK has not been executed. No Android device was
  connected, and Android's dynamic linker cannot be run on the build machine.
  Its object files, linked statically and run under qemu, pass the same 18
  tests, and for 26 rig models on Hamlib's own simulators they answer the app's
  commands exactly as the host build does.
- Hamlib 4.5.5 and 4.7.2 were compared on the app's commands across those
  simulators. Most differences came from the simulators themselves. They were
  followed up for the K3, FT-991, IC-705, IC-7000, IC-7100, IC-7610, TS-590 and
  QRP Labs only.
- Nothing here ran with a radio. Hamlib changed for three years between the two
  versions, and that can change how a particular radio behaves. If CAT worked
  with your radio in v1.6.31 and does not in this version, please open an issue
  with the CAT log. Android does not install an older version over a newer one:
  going back means uninstalling, which deletes the app's data.
- Hamlib 4.7.2 does not connect to a QRP Labs radio that does not answer its
  firmware-version query (`VN;`).
- The X6200 is given the short CAT timeouts of the other Xiegu radios by
  assumption.
- The daemon's build is reproducible: two builds in different directories give
  the same file, and its SHA-256 is in `tools/hamlib/librigctld.so.sha256`. The
  debug APK packages that file unchanged.
- Arm64 Debug APK built with NDK 28.2; version code `10636`, version name
  `1.6.36-hamlib-4.7.2`. The release workflow verifies the signed APK against
  the existing certificate.
- v1.6.34 and v1.6.35 are not releases: those numbers are used by changes that
  are not part of this version.

See [how the bundled rigctld is built and patched](https://github.com/pepefrog1234/RADE_decode_Android/blob/v1.6.36/tools/hamlib/README.md).
