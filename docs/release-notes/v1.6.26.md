# v1.6.26 — TX cadence and clearer callsign display

Version: `1.6.26-tx-cadence-callsigns` / `versionCode 10626`.

## Changes

- Label the receiver's retained callsign as **Last decoded callsign**, with
  an explanation that it arrives at the end of a transmission. This avoids
  mistaking the previous participant for the current speaker in a RADE V1 QSO.
- Enlarge map callsigns to bold 16 sp (18 sp during TX) and details to 12 sp,
  respecting screen density and Android font settings.
- Prevent TX from starting while the radio connection is being established or
  recovered, including the interval when Icom UDP audio is up but CAT is not.
- Fix an extra 20 ms wait after the first network TX frame. After a stall with
  no spare encoder frames, wait one frame period before reading again.
- Record actual send-gap maxima and native encoder underruns in the Audio Log
  to distinguish scheduling delays from zero-padded modem audio.

## Validation

- `testDebugUnitTest assembleDebug assembleDebugAndroidTest --offline` passes:
  **108 JVM tests, zero failures/errors/skips**, including two new TX pacing
  regressions. The eight-case pacing suite reproduces failures on the old code
  and passes after the correction.
- Native arm64, Debug APK and instrumentation APK builds pass. Physical phone
  and IC-7300MK2 validation remains outstanding.

The tester reports that v1.6.25 frequency Set and two LTE/VPN QSOs worked. The
intermittent steady-state TX audio gaps are not yet fully explained; these
fixes must not be taken as proof that every interruption is resolved. See the
[investigation and field-test notes](https://github.com/pepefrog1234/RADE_decode_Android/blob/v1.6.26/docs/diagnostics/icom-tx-callsigns-v1.6.26.md).
