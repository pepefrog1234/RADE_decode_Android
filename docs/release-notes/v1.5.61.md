# v1.5.61 — ネットワーク送信で「送信マイク」の選択が効かないバグを修正

ご報告ありがとうございます。**アプリのバグでした。** インストールは `app-debug.apk` をご利用ください。

## 症状と原因

USB ヘッドセット接続時、ヘッドホン出力は切り替わるのに、送信マイクは設定画面で USB headset を選んでも**内蔵マイクのまま**でした。

原因：ネットワーク接続（**HL2 (LAN)** および **Wi-Fi (IC-705)**）での送信コードが、設定の「送信マイク」の選択を無視して常に内蔵マイクを使う古い実装のままでした。「フルワイヤレス運用では USB 機器を接続しない」という当時の前提によるもので、USB 接続の無線機では正しく切り替わるのに、ネットワーク送信だけ取り残されていました。HL2 (LAN) + USB ヘッドセットという構成でこの前提が崩れ、表面化したものです。

## 修正内容

ネットワーク送信でも USB 無線機と同じマイク解決処理を通すようにしました：

- 設定 →「送信マイク」で選んだ **USB／有線マイクがネットワーク送信でもそのまま使われます**
- 未選択、または選択したデバイスが取り外されている場合は、これまでどおり内蔵マイクに自動フォールバック
- 送信開始時にデバイス一覧を再取得するため、直前に挿した USB ヘッドセットも確実に認識されます

## 確認方法

1. v1.5.61 に更新
2. USB ヘッドセットを接続し、設定 →「送信マイク」で USB headset を選択
3. HL2 (LAN) で接続 → 受信開始 → 送信し、ヘッドセットのマイクで変調されることをご確認ください

いつも早く正確なご報告をありがとうございます。

## English summary

Fixes: in network rig modes (**HL2 (LAN)** and **Wi-Fi (IC-705)**), TX
always captured the **built-in mic**, ignoring the Settings → TX Mic
selection — the mic picker (added in v1.5.39) was only wired into the
USB-rig path, and the network path kept the old "full wireless = no USB
devices" assumption. A USB headset alongside an HL2 (LAN) session broke
that assumption: headphone output followed the selector, the mic didn't.

Network TX now resolves the mic exactly like the USB path: the chosen
USB/wired mic is used, with automatic fallback to the built-in mic when
nothing is selected or the device is unplugged, and the device list is
refreshed at TX start.
