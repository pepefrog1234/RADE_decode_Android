# v1.6.22 — FT-897 CAT 通信・送信失敗時の受信復帰

Version: `1.6.22-ft897-rx-recovery` / `versionCode 10622`.

## 日本語

FT-897 をサウンドカードと USB シリアルで接続した際の「リグ画面にモードが表示されない」「送信しようとすると受信画面が『開始』に戻る」という報告を受け、通信設定と受信復帰処理を修正しました。

- FT-897／FT-897D 選択時、USB シリアルアダプターを **8N2（8 ビット・パリティなし・ストップビット 2）** に設定します。従来の 8N1 との不一致を修正しました。通信速度は無線機と同じ値を選んでください。
- PTT が拒否された場合や送信音声を開始できない場合、送信停止・PTT 解除処理を行ってから受信の再開を試み、画面にエラーを表示します。受信も再開できなかった場合は、その旨を表示します。
- 復帰処理中に「停止」または切断を行うと、自動で受信を再開しません。「停止」時は PTT 解除処理を継続します。
- 送信終了信号と送信末尾の待機、CAT の PTT OFF 順序、解除を確認できない場合のバックグラウンド再試行を維持しています。

**FT-897 実機での動作確認は未実施です。** 更新後はモード・周波数表示と繰り返しの送受信切り替えをご確認ください。再発した場合は、問題直後の CAT ログをお送りください。

## 繁體中文

針對 FT-897 使用音效卡與 USB 串列連線時，Rig 畫面不顯示模式、嘗試發射後接收畫面回到「開始」的回報，修正通訊設定與接收恢復流程。

- 選擇 FT-897／FT-897D 時，實際 USB 串列介面改用 **8N2（8 資料位元、無同位檢查、2 停止位元）**，修正原本固定 8N1 的不相容設定。通訊速率仍需與電台一致。
- PTT 被拒絕或發射音訊啟動失敗時，先停止發射並執行 PTT 解除，再嘗試恢復接收，並顯示錯誤。接收若無法恢復，也會顯示提示。
- 恢復途中按「停止」或中斷連線，會取消自動恢復接收；按「停止」時仍會繼續完成 PTT 解除。
- 保留送信結束訊號與尾音等待、CAT PTT OFF 命令順序，以及無法確認解除時的背景重試。

**尚未使用 FT-897 實機驗證。** 更新後請確認模式與頻率讀取、反覆接收／發射切換；若問題再現，請提供當下的 CAT log。

## Technical validation

- Physical UART framing is applied for FT-897 and FT-897D through CDC, CP210x, FTDI and CH340 setup, including USB permission completion. Failed framing requests abort connection setup. Other rig models retain 8N1.
- RX recovery preserves PTT cleanup while guarding against Stop, disconnect and a replaced audio service. Rapid re-key waits for RX restoration; uncertain PTT OFF continues to block new TX while allowing RX.
- `./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest` passed: **74 JVM unit tests, zero failures/errors/skips**; debug and Android instrumentation test APKs built successfully.
- Tests cover USB framing requests and RX recovery ordering/cancellation. No Android device was attached, so instrumentation tests and physical FT-897/audio validation have not run.
