# v1.6.31 — USB TX microphone compatibility retry

Adds a different microphone capture configuration when USB TX recovery repeatedly
loses the built-in microphone. The October 11 report showed that v1.6.30 correctly
released PTT and restored RX, but reopening the original capture settings did not
restore usable speech.

Install the signed **`app-release.apk`** attached to this release.

## English

- For built-in microphone → USB audio TX, a capture failure now triggers a retry
  with VoiceRecognition at 48 kHz. The initial capture remains unchanged; both
  allowed recovery attempts use the compatibility profile.
- Preserve explicit microphone selection, reset the input filter before capture
  restarts, and retain bounded recovery with PTT release if it fails.
- Scope the profile using actual input/output device types. Bluetooth microphones,
  network TX and local RX-keep-alive monitoring retain their existing policies.
- Log the capture API, preset, sample rate, sharing mode, device types and Android
  version to make subsequent device reports more useful.

## 繁體中文

- 針對「內建麥克風 → USB 音訊輸出」發射時反覆斷線，新增 48 kHz、
  VOICE_RECOGNITION 相容性重試；首次錄音設定維持原樣。
- 保留每次發射最多兩次恢復、指定麥克風路由檢查，以及失敗後解除 PTT、
  恢復接收的保護。藍牙麥克風、網路發射及本機監聽不套用此設定。
- 增加錄音 API、實際設定、裝置類型與手機／Android 版本診斷資訊。
- 這版提供不同的錄音配置，仍須由受影響手機實測，尚未確認已恢復正常通話。

## 日本語

- 内蔵マイクから USB オーディオへ送信する際、入力の切断後に
  48 kHz・VOICE_RECOGNITION で開き直す互換設定を追加しました。
  最初の録音設定は変更せず、復旧時にこの設定へ切り替えます。
- 1回の送信につき最大2回までの復旧と、復旧できない場合の PTT OFF・
  受信への復帰を維持しています。Bluetooth マイクやネットワーク送信には
  この互換設定を適用しません。
- 前回のログではマイク入力の再切断を確認しましたが、Android 側の原因は
  まだ特定できていません。本版で継続して音声を送信できるか、該当端末での
  確認が必要です。

## Validation and limits

- JVM unit tests: 147 passed; 9 optional real-Hamlib integration tests skipped
  because `RADE_TEST_RIGCTLD` was not configured.
- Seven native watchdog regression scenarios passed with C++11 and
  `-Wall -Wextra -Werror`, including recovery-profile escalation, session reset,
  stale callbacks and isolation from noneligible routes.
- Arm64 Debug APK built successfully; version code `10631`, version name
  `1.6.31-usb-mic-compat`.
- The release workflow verifies the signed APK against the existing certificate.
- No Android device was connected. The alternative profile is not yet confirmed
  to resolve the affected phone's repeated disconnections. Sustained capture and
  intelligible transmitted speech still require hardware validation.

See [diagnostic evidence and hardware checks](https://github.com/pepefrog1234/RADE_decode_Android/blob/v1.6.31/docs/diagnostics/tx-microphone-disconnected.md).
