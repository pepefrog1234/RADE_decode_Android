# v1.6.30 — TX microphone disconnect recovery

Fixes missing recovery after the TX microphone reports `ErrorDisconnected`.
Previously, the encoder could send about five seconds of generated silence,
then run out of audio while PTT remained active.

Install the signed **`app-release.apk`** attached to this release.

## English

- Reopen a disconnected or stalled TX microphone, allowing up to two recovery
  attempts per transmission. Detect missing initial callbacks after five seconds
  and stalled capture after 1.5 seconds; quiet microphone samples remain valid.
- Preserve the modem and output path during microphone recovery. Rebuild the
  input filter for the negotiated sample rate and restore Bluetooth input-effect
  settings when applicable.
- If microphone recovery fails, stop TX audio, request PTT OFF, and restore RX
  with an error message. PTT OFF continues retrying if the radio does not confirm
  it. Failure cleanup skips normal EOO and tail delays.
- Ignore late callbacks from retired input streams. Stop/disconnect prevents
  automatic RX restoration, and a previous failure cannot cancel a new TX.
- Preserve compatibility with older Android/OpenSL ES devices that cannot report
  the routed microphone ID.

## 繁體中文

- 修正 TX 麥克風斷線後只記錄錯誤、沒有恢復，造成補送約五秒靜音編碼後無聲，
  但 PTT 仍維持發射的問題。
- 麥克風斷線或停止提供音訊時，每次發射最多重開兩次；安靜但仍有音訊回呼
  不會被誤判故障。恢復期間保留數據機與輸出路徑。
- 恢復失敗時停止發射音訊、要求解除 PTT、恢復接收並顯示錯誤；電台未確認
  PTT OFF 時持續重試。故障清理不等待一般 EOO 與發射尾延遲。
- 防止舊串流回呼干擾新發射；按下 Stop 或斷線後，不會因延遲故障事件重啟接收。
- 保留舊版 Android／OpenSL ES 無法回報麥克風裝置 ID 時的相容性。

## 日本語

- 送信マイクが `ErrorDisconnected` で切断された後に復旧せず、約5秒の無音符号化
  データ送出後に音声が止まっても PTT が有効なままになる問題を修正しました。
- マイク入力の切断・停止を検出し、1回の送信につき最大2回まで入力を開き直します。
- 復旧できない場合は送信音声を停止し、PTT OFF を要求して受信に戻り、エラーを
  表示します。無線機から確認が取れない場合は PTT OFF の再試行を続けます。
- 古い音声ストリームの通知が新しい送信に影響しないようにし、Stop 後に自動で
  受信が再開することを防ぎました。

  because `RADE_TEST_RIGCTLD` was not configured.
- Six native watchdog regression scenarios passed with C++11 and
  `-Wall -Wextra -Werror`.
- Debug APK built successfully; version code `10630`, version name
  `1.6.30-tx-mic-recovery`.
- The release workflow builds and verifies the signed APK against the existing
  release certificate before publishing it.
- No Android device was connected. Recovery on the affected phone, the underlying
  Android routing trigger, and over-the-air speech still need hardware validation.
