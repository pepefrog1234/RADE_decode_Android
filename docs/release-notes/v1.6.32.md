# v1.6.32 — RADE modem updated to upstream rade_c (November 2026)

Updates the built-in RADE modem from the July 2026 snapshot (`e509f11`, when the
project was still called radae_nopy) to current upstream
[freedv/rade_c](https://github.com/freedv/rade_c) `be66f39` — 72 upstream commits,
library API 2.1 → 2.4. V1, the default waveform, keeps the same on-air signal and
decodes the same. Most upstream fixes are for the experimental V2 waveform.

Install the signed **`app-release.apk`** attached to this release.

## English

**V1 (default waveform)**

- Same signal on the air: transmit audio differs from v1.6.31 by at most one
  16-bit step, and v1.6.31 and v1.6.32 decode each other with identical quality.
- Upstream receiver fixes: pilot equaliser interpolation, the SNR reading no
  longer sags at the end of an over, and phase rotators are renormalised so long
  overs do not drift.
- The end-of-over callsign fix this app carried as a local patch is now upstream,
  so the modem source is an unmodified copy of upstream again.

**V2 (experimental — Settings → RADE Mode)**

- Input AGC. V2 only decoded cleanly when the audio reaching the modem was above
  about −12 dBFS RMS, and produced garbage below about −24 dBFS; it now decodes
  cleanly down to about −42 dBFS.
- Sound-card clock offset. Five-minute overs with a 30–120 ppm offset between
  the two stations' sound cards lost sync one to three times and garbled; they
  now decode cleanly without a single re-sync.
- A signal more than ±31 Hz off frequency is no longer decoded as garbled
  speech: the receiver stays in search until it is tuned within range. The
  library's new tune-up/down hint is not shown in the UI yet.
- Upstream's transmit band-pass filter (300–2700 Hz) cuts energy outside the SSB
  passband from −30 dB to −51 dB of total power. Transmit level is unchanged.
- Fixed a crash at the end of a received V2 over: the V1 callsign decoder was
  run on V2's empty end-of-over payload.
- V2 is still experimental upstream and not interoperable with V1. Leave it OFF
  for normal operation.

**Under the hood**

- The modem is compiled without `-ffast-math`, which upstream now requires (it
  refuses to build otherwise). Opus/FARGAN and the rest of the native code are
  built as before.
- Modem input uses the library's documented int16 scaling for real-valued audio
  (×2/16384). V1 decodes identically at any level, so only V2 is affected.
- `tools/radecheck` loopback now also checks the end-of-over frame (V1 payload
  bits, V2 detection).

## 繁體中文

**V1（預設波形）**

- 空中訊號不變：發射音訊與 v1.6.31 最多只差 16-bit 的一個量化階，新舊版本
  互相解碼的品質完全相同。
- 納入上游的接收修正：導頻等化器的內插位置、發話結束時 SNR 讀數不再下滑、
  相位旋轉器重新正規化（長時間發話不會漂移）。
- 本 app 原本自行修補的「發話結束（EOO）呼號解調」已由上游採納，數據機原始碼
  回到與上游完全相同、沒有本地修改的狀態。

**V2（實驗性，設定 → RADE 模式）**

- 輸入 AGC：過去送進數據機的音量要高於約 −12 dBFS RMS 才能正常解碼，低於約
  −24 dBFS 就只剩雜音；現在低到約 −42 dBFS 仍能正常解碼。
- 聲卡時脈偏差：兩端聲卡相差 30–120 ppm 時，五分鐘的發話過去會失去同步
  一到三次並出現雜音，現在全程不需重新同步。
- 頻率偏差超過 ±31 Hz 的訊號不再被解成雜亂語音，接收端會停在搜尋狀態，
  直到調到範圍內。函式庫新增的「往上／往下調」提示尚未顯示在介面上。
- 上游新增的發射帶通濾波器（300–2700 Hz）把 SSB 通帶外的能量由總功率的
  −30 dB 降到 −51 dB，發射電平不變。
- 修正收到 V2 發話結束時的當機：程式把 V1 的呼號解碼器套用在 V2 空的
  EOO 資料上。
- V2 在上游仍屬實驗階段，且與 V1 不相容，一般通聯請維持關閉。

**內部變更**

- 數據機改為不使用 `-ffast-math` 編譯（上游現在強制要求，否則無法編譯）；
  Opus／FARGAN 與其他原生程式的編譯方式不變。
- 數據機輸入改用函式庫文件規定的實數音訊 int16 換算（×2/16384）。V1 在任何
  音量下解碼結果都相同，只有 V2 受影響。
- `tools/radecheck` 的 loopback 檢查新增發話結束訊框的驗證（V1 資料位元、
  V2 偵測）。

## 日本語

**V1（標準の波形）**

- 電波に出る信号は変わりません。送信音声の v1.6.31 との差は 16 ビットの
  1 ステップ以内で、新旧どちらの組み合わせでも同じ品質で復調できます。
- upstream の受信側修正を取り込みました：パイロット等化の補間位置、送信終了時に
  SNR 表示が下がる問題、長い送信での位相ドリフト（位相回転の再正規化）。
- 本アプリが独自に当てていた EOO コールサイン復調の修正は upstream に取り込まれ、
  モデムのソースは upstream と同一（ローカル修正なし）に戻りました。

**V2（実験的 — 設定 → RADE モード）**

- 入力 AGC：これまではモデムに入る音声が約 −12 dBFS RMS より大きくないと正常に
  復調できず、約 −24 dBFS 以下ではノイズになっていました。約 −42 dBFS まで正常に
  復調します。
- サウンドカードのクロックずれ：両局のずれが 30〜120 ppm あると、5 分間の送信で
  1〜3 回同期が外れて音声が乱れていました。再同期なしで復調できます。
- ±31 Hz を超えて周波数がずれた信号を、乱れた音声として復調しなくなりました。
  範囲内に合わせるまで受信機はサーチのままです。ライブラリに追加された
  「上げる／下げる」表示はまだ UI に出していません。
- upstream の送信バンドパスフィルター（300〜2700 Hz）により、SSB 通過帯域外の
  エネルギーが全電力比 −30 dB から −51 dB に下がります。送信レベルは同じです。
- V2 の送信終了を受信した瞬間にアプリが落ちる問題を修正しました（V1 用の
  コールサイン復調を、データのない V2 の EOO に対して実行していました）。
- V2 は upstream でもまだ実験段階で、V1 との互換性はありません。通常の運用では
  OFF のままにしてください。

**内部の変更**

- モデムを `-ffast-math` なしでコンパイルします（upstream が必須とし、付けると
  ビルドできません）。Opus／FARGAN とその他のネイティブコードは従来どおりです。
- モデム入力を、ライブラリが定める実数音声の int16 スケーリング（×2/16384）に
  合わせました。V1 はどの音量でも復調結果が同じで、影響があるのは V2 だけです。
- `tools/radecheck` の loopback が送信終了フレーム（V1 のデータビット、V2 の
  検出）も確認するようになりました。

## Validation and limits

- Upstream's feature-loss test, run through this app's int16 TX/RX conversions on
  an x86-64 host with `wav/all.wav`: V1 0.114 before and after (upstream
  reference 0.113, pass limit 0.119); V2 0.083 → 0.079 (reference 0.084, limit
  0.088).
- Two upstream off-air V1 recordings (5.5 and 10 minutes) decode into the same
  overs with the same callsigns (VK5KVA, VK3TPM, G4HJW) before and after; the one
  difference is an over without an end-of-over frame being dropped a second
  sooner. Old ↔ new decoding was checked in both directions for V1 and V2.
- V2 five-minute overs at +30, −60 and +120 ppm: loss 0.27 / 1.44 / 1.67 before,
  0.083 / 0.084 / 0.089 after. V1 is unaffected by clock offset in either version.
- 20 scenarios (noise, level, frequency offset, clock offset, noise only, both
  waveforms) under AddressSanitizer and UBSan: no reports. `tools/radecheck`
  loopback and audiocheck pass; the new end-of-over check fails as intended
  (30 of 180 bits wrong) on upstream's old, unpatched EOO demodulator.
- JVM unit tests: 147 passed; 9 optional real-Hamlib integration tests skipped
  because `RADE_TEST_RIGCTLD` was not configured.
- Arm64 Debug APK built with NDK 28.2; version code `10632`, version name
  `1.6.32-rade-c-update`. The same arm64 modem build, run under QEMU, matches the
  x86 results. The release workflow verifies the signed APK against the existing
  certificate.
- No Android device or radio was connected, so on-air behaviour and on-device CPU
  load are unverified. On the x86 host, V1 signal search costs 6.5× less CPU
  (16.9% → 2.6% of one core). That gain does not carry over to phones: the old
  arm64 build was already vectorised by fast math, and a CPU-model estimate puts
  the new search loop at roughly 1.3–1.6× the old one — a few milliseconds more
  per 120 ms frame while searching on V1. Worth a battery/CPU check on a phone.
- The V2 end-of-over crash is the one reported from on-air use in
  [issue #29](https://github.com/pepefrog1234/RADE_decode_Android/issues/29),
  where the receiving phone crashed each time a V2 over ended. The fix was checked
  on the host by making the same call the app made; it has not been run on a
  device.
