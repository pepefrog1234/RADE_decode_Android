# v1.5.70 — PureSignal：TX エンベロープのクリップと補正ドメイン超過を修正

ログの送付ありがとうございました。まず重要なお知らせです：**v1.5.69 はリリース作成が漏れており、未配布でした。** 今回いただいたログは v1.5.68 形式（`ps=[cals=...]`、毎秒の連続校正）であり、前回と同じ APK での試験になっていました。「昨日と同じ結果」になったのはこのためです。申し訳ありません。v1.5.70 には v1.5.69 の全修正（extended feedback gain 形式、one-shot 校正、overflow バックオフ等）が含まれています。

その上で、今回のログから **補正が IMD を悪化させる方向に働く根本原因の候補** を新たに特定し、修正しました。

## 今回のログの決定的な証拠

`rx2Ref`（HL2 内部の TX DAC リファレンス）のピーク値が、**全ての 1 秒区間・両バンド（20m/80m）・PureSignal ON/OFF の全てで -12.4 dBFS に張り付いて** いました。-12.4 dBFS = 0.240 はちょうど HL2 の DAC フルスケール基準値（hwPeak）です。これは、アプリが送信する int16 波形が常に ±32767 の上限に当たって方形クリップしていたことを意味します。

## 原因

解析信号（I/Q）のエンベロープピークを ~0.5 と想定して ×2.0 の正規化を行っていましたが、クランプ済み RADE 波形のエンベロープは波形自体より約 25% 高く、実測では ≥0.625 でした。その結果：

1. **int16 変換段で方形クリップ**（I と Q を別々にクランプするため位相まで歪む）。PS OFF でも発生しており、これが従来の IMD ショルダーの一因です。
2. **WDSP の補正ドメイン [0,1] を最大 ~1.25 まで超過**：
   - 補正器（iqc）は最上位ビンの三次スプラインを 25% も外挿し、最も強いサンプル群に誤った補正量を適用
   - 校正（calcc）はエンベロープ >1.0 のサンプルを収集から破棄するため、クリップ・圧縮が起きている領域が学習データに一切入らない
   - 補正器が PA 圧縮の逆特性でピークをさらに持ち上げ、クリップへ深く押し込む
3. 校正のたびにこのループが繰り返され、**補正方向が IMD を悪化させる** というスペクトラム上の観測と一致します。

## 修正内容

- TX スケールと PS 正規化を実測ピーク基準に修正（×2.0 → ×1.6）。int16 クリップを除去
- PS 経路に radial（位相保存）エンベロープリミッタを追加し、補正ドメインを正確に [0,1] に維持（最上位ビンへのサンプル供給も保証）
- TX health に `env=ピーク/制限サンプル数` 診断を追加 — 次のログで実機の真のエンベロープピークが判ります
- PureSignal controller を再設計：
  - RX1/RX2 比による preflight ゲートを廃止（HL2 は最小 gain でも比が高く、必ず STOP して校正に到達できなかった）。WDSP 自身の feedback level fit（fblvl、目標 140..165）を唯一の判定基準に変更
  - 最小 gain で fblvl が 166..200 の場合は使用可能として LOCK（今回の実測 181@20m を許容）
  - LOCKED 後の瞬間的な ADC overflow で確定済み補正を破棄しないように変更
  - 最小 gain での過渡的 overflow を PTT ごとに 3 回まで許容（1 回で恒久停止しない）
  - リトライ期限を 8 秒 → 20 秒に延長

## ご注意（重要）

- **TX 出力が約 2 dB 下がります。** これまでクリップで失われていた分の正常化です。必要であれば Drive を 128 → 160 目安に上げてください。
- PS OFF でもクリップが除去されるため、**OFF 時の IMD ショルダーも少し改善する可能性** があります。ON/OFF 比較は同じ Drive 設定で行ってください。

## 再テストのお願い

PureSignal ON で送信し、新しいログで以下をご確認ください：

- `env=` が 1.00 前後（1.10 を大きく超える場合はお知らせください — 正規化をさらに調整します）
- `rx2Ref` のピークが -12.4 dBFS に張り付かず変動すること（クリップ解消の確認）
- gain が数回変化した後 `ctl=LOCKED`、`ok=` が 1 以上、`fblvl=` が 140..200
- その状態でのスペクトラムの IMD ショルダーの変化（ON/OFF 比較）

## English summary

The tester's log was produced by v1.5.68 — the v1.5.69 tag/release was never
published (process fault), so "same result as yesterday" was literal. Beyond
that, the log contains hard evidence of the real defect: the RX2 DAC-loopback
reference peak sat pinned at -12.4 dBFS (= the 0.240 HL2 hwPeak, i.e. DAC full
scale) in every interval, both bands, PS on and off. The analytic envelope of
the clamped RADE waveform peaks at ≥0.625 (not the assumed 0.5), so the ×2.0
normalization both square-clipped the int16 wire stage and overflowed WDSP's
[0,1] correction domain to ~1.25 — the corrector extrapolated its top spline
by 25%, CALCC discarded every sample in the clipping region, and each
calibration pushed peaks deeper into the rail: correction moved IMD in the
wrong direction, exactly as observed on the spectrum. v1.5.70 rescales the TX
chain to the measured peak (×1.6), adds a phase-preserving radial envelope
limiter and an `env=` diagnostic, and makes WDSP's own fblvl the single gain
authority in the controller (the RX1/RX2 ratio preflight could never pass on
HL2 and would have stopped all calibration). TX output drops ~2 dB (the
formerly clipped headroom); raise Drive to compensate if needed.
