# v1.5.64 — PureSignal 対応・第 1 段階（フィードバック取得と診断）

お待たせしました — **HL2 (LAN) への PureSignal 組み込みを正式に開始します**。改めて検討した結果「実現可能」と判断し、3 段階の計画で進めます。本バージョンはその第 1 段階です。インストールは `app-debug.apk` をご利用ください。

## 計画の全体像

1. **第 1 段階（本バージョン）**：送信フィードバックの取得と計測 — HL-2 のゲートウェアが送信中に PA のサンプルを第 2 受信ストリームで返す経路を有効化し、レベルを診断ログに記録します
2. **第 2 段階**：補正エンジンの組み込み — Thetis と同じオープンソースの WDSP（PureSignal の本体）をアプリ内に移植し、送信 I/Q に予歪み補正を適用します
3. **第 3 段階**：実機での収束調整 — massacho さんのテストとログを頼りに、フィードバックレベル・収束の安定性を詰めます

## 本バージョンの変更（内部）

- 受信機を 2 系統構成に変更（RX1 = 通常受信、RX2 = PureSignal フィードバック用・送信周波数に自動追従）
- ゲートウェアの PureSignal フィードバック経路を有効化（プロトコルの PS ビット）
- 送信中のフィードバック用ゲイン（LNA）レジスタを設定（第 1 段階は 0 dB 固定）
- 送信中、**両方の受信ストリームのレベルを毎秒計測**し、`TX health` ログに `| PS: fb1=… fb2=…（dBFS）` として記録 — どちらの受信機にフィードバックが乗っているか、レベルが適正かを実測で確定します
- 付随する最適化：送信中の不要な受信 DSP を停止、待機時の上りパケットレートを従来水準に調整

## お願い：2 点のご確認

1. **通常の受信がこれまでどおり完璧か** — 本バージョンは無線機からのデータ形式が 2 受信機構成に変わるため、まず受信の確認をお願いします（受信・切替・コールサイン表示など普段どおりの動作確認で十分です）
2. **送信を数秒 → 設定 → 診断 → Capture audio log** — `TX health` 行の `fb1=`／`fb2=` の値が第 2 段階の設計材料になります（フィードバックがどちらに乗るか・レベルが飽和していないか）

いつもありがとうございます。PureSignal まであと 2 段階です。

## English summary

**PureSignal for HL2 (LAN) — Phase 1 of 3 (feedback capture &
diagnostics).** After re-evaluating, in-app PureSignal is feasible: the
HL2 gateware returns a TX feedback sample stream via a second protocol-1
receiver, and the correction engine (WDSP, the same open-source code
Thetis uses) is portable C well within a phone's CPU budget (project is
GPL-cleared for Phase 2).

This release configures **two receivers** (RX1 = normal receive, RX2 =
PS feedback tracking the TX frequency), enables the gateware's
PureSignal feedback routing (addr 0x0A bit 22), programs the TX-time
LNA/feedback gain register (addr 0x0E, 0 dB for now), and **measures
both receivers' RMS/peak levels every second during TX**, logged as
`| PS: fb1=… fb2=… dBFS` in the TX-health line — empirically pinning
down which receiver carries the feedback and whether the level suits
the ADC before Phase 2 (WDSP port + predistortion apply) begins.

Please verify (1) normal RX is unaffected by the 2-receiver layout and
(2) capture a TX log so we can read the fb1/fb2 levels.
