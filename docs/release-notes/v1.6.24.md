# v1.6.24 — Preserve frequency entry and verify Set readback

Version: `1.6.24-frequency-entry` / `versionCode 10624`.

## Changes

- Keep the operator's edited frequency intact when background polling updates
  the radio frequency. A submitted value remains available for retry until
  the reported frequency matches it.
- Accept either a decimal point or decimal comma in kHz input, preserve 1 Hz
  precision, and reject invalid or ambiguous entries without deleting their
  characters. This fixes locale formatting that could turn `5357,5` into
  `53575` during editing.
- Allow 2.5 seconds for a frequency Set reply and separately 2.5 seconds for
  readback on the same connection. Show a warning when readback is missing or
  different; perform the automatic band mode change only after a matching
  readback. A later matching poll clears the warning.
- Ignore polls predating a newer Set, cancel superseded frequency jobs, and
  prevent an old request from continuing on a replacement connection. Preserve
  reply ordering for commands already sent before cancellation.
- Record frequency requests and completed frequency replies, including late
  replies, in the existing Audio Log capture.

## Validation

- `testDebugUnitTest assembleDebug assembleDebugAndroidTest --offline` passed:
  **98 JVM tests, zero failures/errors/skips**.
- Eleven new input and TCP regression tests cover precision, decimal commas,
  edits during polling, delayed/mismatched replies, cancelled requests, late
  confirmation, and replacement connections.
- Android instrumentation APK compiles; physical phone/radio tests have not run.

The tester's v1.6.21 excerpt contains no Set command or actual frequency values,
so these fixes do not establish the exact cause of the physical IC-7300MK2
frequency jump. Hamlib readback may use a cache; verify the radio's display
during field testing. See the [diagnostic and field-test notes](https://github.com/pepefrog1234/RADE_decode_Android/blob/v1.6.24/docs/diagnostics/icom-frequency-entry.md).
