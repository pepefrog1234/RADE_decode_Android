# RADE_decode — Android 用 FreeDV RADE デジタル音声トランシーバー

![Platform](https://img.shields.io/badge/platform-Android%208.0%2B-3DDC84?logo=android&logoColor=white)
![ABI](https://img.shields.io/badge/ABI-arm64--v8a-blue)
![License](https://img.shields.io/badge/license-LGPL--2.1-orange)

[English](README.md) | [繁體中文](README.zh-TW.md) | [简体中文](README.zh-CN.md) | **日本語**

**RADE_decode** は、Android スマートフォンを完全な **FreeDV RADE** HF デジタル音声
トランシーバーに変えるアプリです。RADE（Radio Autoencoder）波形をリアルタイムで
受信**および送信**でき、ニューラルボコーダーを含むすべての処理が端末上で完結します。
PC 上の FreeDV（freedv-gui 2.x）の RADE V1 モードを運用している局と交信可能です。

USB オーディオでスマートフォンを HF SSB リグに接続するか、Icom IC-705 なら Wi-Fi で
完全ワイヤレス接続するだけで、CAT リグ制御、FreeDV Reporter へのスポット送信、
リアルタイム局マップ、自動受信ログを備えたポケットサイズの RADE 局が完成します。

---

## RADE とは？

[RADE](https://github.com/drowe67/radae)（Radio Autoencoder）は、David Rowe 氏と
[FreeDV](https://freedv.org) プロジェクトが開発した機械学習ベースのデジタル音声
モードです。従来の「音声コーデック + FEC + モデム」という構成ではなく、ニューラル
ネットワークが音声を直接 OFDM シンボルへ変換・復元し、音声合成には Opus プロジェクト
の **FARGAN** ニューラルボコーダーを使用します。従来の HF デジタル音声モードを
はるかに超える音質を実現し、アナログ SSB では交信が困難な低 SNR でも明瞭に
復調できます。

本アプリは RADE V1 の信号チェーン全体をスマートフォン上でネイティブ実行します：

- **モデム：** RADE V1 OFDM、30 キャリア、8 kHz で処理（FreeDV Reporter には
  モード `RADEV1` として報告）
- **ボコーダー：** FARGAN @ 16 kHz、CPU のみで動作——インターネットも GPU も不要
- **コールサイン：** EOO（End-Of-Over）フレームにより、各送信（オーバー）の
  終わりにコールサインをエンコード／デコード

## 主な機能

**受信**
- 48 kHz の任意の音声ソース（USB オーディオインターフェース、リグ内蔵 USB
  サウンドカード、内蔵マイク）から RADE 信号をリアルタイムデコード
- キャリアマーカー付きのリアルタイムスペクトラムとウォーターフォール、SNR、
  周波数オフセット、3 段階の同期表示（サーチ中 → 候補 → 同期済み）
- デコードしたコールサインを画面と通知に表示
- フォアグラウンドサービスによるバックグラウンドデコード——画面を消しても、
  他のアプリを使っていても受信を継続
- 同期した受信は毎回自動的に WAV（デコード後の音声）として録音され、アプリ内で
  再生・共有が可能

**送信**
- フル送信対応：マイク → RADE OFDM 波形 → リグ。コールサインは EOO フレームに
  自動的に埋め込み
- 交信中にワンタップで送受信切り替え。リグ接続時は CAT 経由で PTT を自動制御
- 送信ドライブレベル調整可能、ALC 調整ガイドを UI に内蔵

**リグ制御（CAT）**
- **Hamlib 4.5.5 `rigctld`**（arm64 ネイティブバイナリ）を内蔵——340 種類以上の
  リグに対応、PC 不要
- 3 つの接続モード：
  - **シリアル（ローカル）：** USB CAT ケーブル（OTG）——CDC-ACM、CP210x、FTDI、
    Prolific、CH340/CH341 チップに対応、DTR/RTS 制御可
  - **TCP（rigctld）：** rigctld 互換のリモートサーバーに接続。Thetis / Quisk /
    SparkSDR / piHPSDR 向けの **Hermes-Lite 2** プロファイルも用意
  - **Wi-Fi（IC-705）：** Icom 純正ネットワークプロトコル（RS-BA1）——CAT 制御
    **と**送受信音声の両方が Wi-Fi 経由、ケーブル一切不要
- 周波数／モード／PTT／S メーターをリアルタイム表示。周波数入力時はサイドバンド
  とデータモードを自動選択（USB/LSB、PKTUSB/PKTLSB）

**FreeDV Reporter 連携**
- [qso.freedv.org](https://qso.freedv.org) と双方向接続：受信スポット
  （コールサイン + SNR）、送信状態、周波数、ステータスメッセージをリアルタイム送信
- **局一覧**タブ：現在オンラインの全局を表示、バンド（160 m – VHF+）で絞り込み可
- **マップ**タブ：OpenStreetMap の世界地図に送信中／受信中／待機中の局を表示。
  大圏コースの伝搬パス（実線 = EOO でコールサイン確認済み、破線 = 同一周波数から
  推定）と各パスの SNR バッジ付き
- GPS からグリッドスクエア（Maidenhead ロケーター）を自動計算・自動更新

**その他の機能**
- 受信ログ：すべての受信セッションをローカルデータベースに保存。SNR 推移グラフ、
  同期イベントのタイムライン、デコード済みコールサイン一覧、信号統計付き
- **省電力モード**：低スペック端末向け（FFT とスペクトラム描画を停止し、CPU を
  デコーダーに集中）
- メーカー別手順付きの「電池の最適化」設定アシスタント（Samsung、Xiaomi、
  Huawei、OPPO、vivo など）
- UI は English、繁體中文、简体中文、日本語に対応

## 動作要件

| | 最低要件 |
|---|---|
| Android | 8.0（API 26）以上 |
| CPU | 64 ビット ARM（**arm64-v8a のみ**——x86 および 32 ビット非対応） |
| 性能 | FARGAN ニューラルボコーダーは CPU で動作。2018 年頃以降のミドルレンジ端末なら十分です。非力な端末では **設定 → 省電力モード** をオンにしてください。 |
| 無線機 | 任意の HF SSB トランシーバー。USB ケーブル 1 本で済ませるなら USB オーディオ + CAT 内蔵機種（IC-7300、IC-705 など）を。それ以外はスマートフォンとリグの間に USB オーディオインターフェース（DigiRig など）が必要です。 |
| アクセサリー | USB-OTG アダプター（USB オーディオ／USB シリアル用）。IC-705 の Wi-Fi モードなら何も不要。 |

> 受信だけならリグ接続は不要です。マイクをスピーカーに近づける（音響カップリング）
> か、USB サウンドカード経由で音声を入力するだけで聴けます。

## インストール

1. [**Releases**](https://github.com/pepefrog1234/RADE_decode_Android/releases)
   ページから最新の APK をダウンロードします。
2. 「提供元不明のアプリのインストール」を許可してインストールします。
3. 初回起動時にマイク権限を許可し、「電池の最適化」ダイアログの案内に従って
   設定してください。バックグラウンドでのデコードが中断されなくなります。

Play ストアでは配信していません。更新は GitHub Release として公開されます。

## クイックスタート — 受信

1. **音声を接続します。** おすすめ順：
   - *USB オーディオ：* OTG アダプターでリグ（またはオーディオインターフェース）を
     スマートフォンに接続し、**設定 → オーディオデバイス → 入力デバイス** で
     選択します。
   - *IC-705 Wi-Fi：* 下記 [Wi-Fi（IC-705）](#wi-fiic-705) を参照——音声はネットワーク
     経由、ケーブル不要です。
   - *マイク：* スマートフォンをリグのスピーカーに近づける方法でも動作しますが、
     USB オーディオの方がはるかに安定します。
2. **リグを** RADE の運用周波数に合わせます。例：20 m バンドの FreeDV 呼出周波数
   **14.236 MHz USB** 付近。**局一覧**タブと
   [qso.freedv.org](https://qso.freedv.org) で、今誰がどの周波数に出ているかを
   リアルタイムで確認できます。
3. **受信機**タブを開き、**開始（START）** を押します。
4. **INPUT** レベルメーターを見ながら、ピークが **−15 〜 −5 dBFS** に収まるよう
   リグの出力または **設定 → 入力ゲイン** を調整します。
5. RADE 信号を受信すると、ヘッダーが「サーチ中 → 同期済み」と変化して音声の再生が
   始まります。相手のオーバー（送信の一区切り）が終わると EOO フレームが送られ、
   その時点でコールサインが表示されます。

同期するたびに受信セッションが自動的に作成されて**ログ**タブに記録され、
デコード音声も WAV として保存されるので、後から再生・共有できます。

## クイックスタート — 送信

> 送信にはアマチュア無線の有効な免許が必要です。

1. **設定 → 送信コールサイン：** 自局のコールサインを入力します（最大 8 文字）——
   毎回のオーバーで EOO フレームに埋め込まれます。
2. **設定 → オーディオデバイス → 出力デバイス：** リグへつながる USB オーディオ
   デバイスを選択します（IC-705 Wi-Fi モードでは不要、送信音声はネットワーク
   経由です）。
3. **開始（START）** を押してから **送信（TX）** をタップし、スマートフォンの
   マイクに向かって話します。**受信に戻る（BACK TO RX）** でオーバー終了
   （このとき EOO コールサインフレームも送信されます）。
4. **レベル調整**——目標はリグの *ALC がほとんど振れない* ことです：
   - 端末の**音量キー**と **設定 → 受信出力 → 音量** が全体の出力を制御、
   - **設定 → 送信出力 → USB 送信レベル** がリグの USB 音声入力へのドライブ量を
     制御、
   - リグ側の USB MOD レベルも確認してください（IC-7300：`メニュー → SET →
     Connectors → USB MOD Level`）。
5. **リグ**タブでリグを接続していれば PTT は自動制御されます。未接続の場合は
   リグの VOX を使うか手動で PTT を押してください。

## リグ制御（CAT）

**リグ**タブを開き、3 つの接続モードから選択します。接続するとリアルタイムの
周波数表示、モード、S メーターが使えるようになり、周波数を直接入力できます——
入力時にはサイドバンドとデータモードが自動選択されます（10 MHz 未満は
LSB/PKTLSB、以上は USB/PKTUSB。データモード非対応機種は通常の USB/LSB に
フォールバック）。

### シリアル（ローカル）— USB CAT ケーブル

本物の Hamlib 4.5.5 `rigctld`（arm64）をアプリに内蔵してスマートフォン上で実行し、
ネイティブの pty ドライバーで USB ケーブルとブリッジします。

1. CAT ケーブルを接続します（CDC-ACM、CP210x、FTDI、Prolific、CH340/CH341
   チップに対応。Xiegu X6100 のような複合デバイスは各ポートが個別に
   リストされます）。
2. **メーカー／モデル**を選択し（340 種類以上の Hamlib モデルを名前または
   Hamlib ID で検索可能）、**ボーレート**を設定します。Icom 機は必要に応じて
   **CI-V アドレス**（16 進数、通常は auto のままで OK）を指定します。
3. **DTR/RTS：** DTR はデフォルトでオン、RTS はオフです——*CAT ケーブルが RTS を
   PTT に配線している場合は RTS をオフのままに*。さもないと接続した瞬間に
   リグが送信状態になります。
4. **接続（CONNECT）** をタップし、USB 権限を許可します。

Xiegu 機（G90、X6100、X5105、X108G）には短い CI-V タイムアウトが自動適用され、
PTT の応答性が保たれます。

### TCP（rigctld）— リモートサーバー

`rigctld` 互換の TCP サーバー（デフォルトポート 4532）に接続します：`rigctld` を
実行している PC、FLRig、SDR ソフトなど。**Hermes-Lite 2** プロファイルを選ぶと
Thetis、Quisk、SparkSDR、piHPSDR の rigctl サーバーに接続できます——ただし音声は
引き続き Android のオーディオデバイス経由です（OpenHPSDR I/Q ストリーミングには
非対応）。

### Wi-Fi（IC-705）

IC-705 内蔵のネットワークサーバー（Icom RS-BA1 プロトコル、UDP ポート
50001/50002/50003）を使った完全ワイヤレス運用：

1. 無線機側：`Set ▸ WLAN ▸ ネットワーク制御 = ON` にし、ネットワークユーザー名／
   パスワードを設定します。
2. スマートフォンを同じネットワーク（または無線機のアクセスポイントモード）に
   接続し、無線機の IP アドレス、ユーザー名、パスワードを入力して
   **接続（CONNECT）** をタップします。
3. CAT 制御**と** 48 kHz の送受信音声の両方が Wi-Fi 経由になります——
   「Audio (Wi-Fi)」インジケーターが緑になれば成功です。USB ケーブルも
   オーディオインターフェースも不要です。

## FreeDV Reporter・局一覧・マップ

**設定 → FREEDV レポーター** を有効にしてコールサインを設定すると、アプリは
qso.freedv.org との接続を維持します：

- デコードした内容はすべてスポットとして送信されます（コールサイン、SNR、周波数）。
  同期中は「受信中」のハートビートも送られ、他の局からあなたのドットが
  リアルタイムで反応して見えます。
- 送信状態とリグの周波数（CAT 接続時）も報告されます。80 文字以内の
  ステータスメッセージも設定可能です。
- コールサイン未設定の場合は閲覧専用（view）モードで接続します——他局の状況は
  同じように見えます。

**局一覧**タブにはオンラインの全局（グリッド、周波数、送信中表示付き）が並び、
バンドで絞り込めます。**マップ**タブはそれらを世界地図に描画します：

| マーカー／線 | 意味 |
|---|---|
| 🔴 赤マーカー | 送信中の局 |
| 🟢 緑マーカー | 受信中の局（周波数 + SNR 表示） |
| ⚪ 灰色マーカー | 待機／ワッチ中 |
| 赤→緑の実線アーク | 確認済みパス——受信側が送信局の EOO コールサインをデコード |
| 青の破線アーク | 推定パス——受信側が同一周波数（±5 kHz）で同期 |
| SNR バッジ | パス中間点に報告 SNR を表示、値に応じて色分け |

## 受信ログ

**ログ**タブにはすべての受信セッションが保存されます（同期が約 2 秒以上途切れる
と自動的に新しいセッションに分割）。セッションをタップすると：

- 開始／終了時刻、継続時間、同期率、モデムフレーム統計、使用オーディオデバイス
- **デコード音声 WAV の再生と共有**
- デコードした全コールサイン（デコード時の SNR とフレーム位置付き）
- 同期状態の背景色付き SNR 推移グラフ、同期イベントのタイムライン、信号サマリー
  （ピーク／平均 SNR、周波数オフセット範囲）

録音はアプリ専用領域に保存され、Android 標準の共有シートからエクスポートできます。

## 設定リファレンス

| 設定 | デフォルト | 説明 |
|---|---|---|
| オーディオデバイス → 入力／出力デバイス | 最初の USB デバイス | キャプチャ／再生デバイスの選択。「更新」で再スキャン |
| 入力ゲイン → デジタルゲイン | 4.0×（12 dB） | 0.1〜30× のソフトウェアゲイン。弱い USB 入力を増幅。ピーク目標 −15…−5 dBFS |
| 受信出力 → 音量 | 100 % | デコード音声の音量。送信出力にも影響 |
| 送信出力 → USB 送信レベル | 20 % | リグの USB 音声入力へ送る RADE 波形のドライブ量 |
| 送信コールサイン → コールサイン（EOO） | — | 最大 8 文字。毎オーバーの終わりに EOO フレームで送信 |
| FREEDV レポーター → レポーター有効化 | オン | qso.freedv.org との常時接続 |
| FREEDV レポーター → グリッドスクエア | GPS から取得 | 6 文字の Maidenhead ロケーター。位置情報権限があれば自動入力 |
| FREEDV レポーター → ステータスメッセージ | — | qso.freedv.org の自局の隣に表示される自由記述（80 文字以内） |
| パフォーマンス → 省電力モード | オフ | スペクトラム／ウォーターフォールを非表示にし **FFT 処理も停止**。低スペック端末でも安定してデコード |

## トラブルシューティング

- **ウォーターフォールに信号は見えるのに同期しない** —— まずサイドバンドを確認
  （10 MHz 以上は USB、未満は LSB）、次に入力レベル（−15…−5 dBFS）。レベルの
  過大・過小が最も多い原因です。
- **オレンジ色の警告「device rejected Unprocessed preset」** —— 端末が選択した
  入力に音声処理（エコーキャンセル／AGC）を強制適用しており、デコードに失敗する
  ことがあります（例：Samsung Galaxy S24 の内蔵マイク）。USB オーディオ入力を
  使ってください。
- **低スペック端末で音が途切れる・ロボットのような声になる** —— **省電力モード**
  をオンに。ボコーダー以外ではスペクトラム描画と FFT が最大の CPU 負荷です。
- **画面を消すとデコードが止まる** —— 「電池の最適化」がサービスを終了させて
  います。初回起動時に表示される電池設定ダイアログ（メーカー別手順付き）に
  従ってください。
- **シリアルケーブルを接続した瞬間にリグが送信状態になる** —— CAT ケーブルが
  RTS を PTT に配線しています。リグタブで **RTS をオフ**にしてください。
- **USB シリアルデバイスが見つからない** —— 端末が USB-OTG に対応しているか確認し、
  **更新**で再スキャン、Android の USB 権限ダイアログを許可してください。
- **IC-705 に Wi-Fi で接続できない** —— ネットワーク制御が ON であること、
  ユーザー名／パスワードが無線機のネットワークユーザー設定と一致していること、
  スマートフォンから無線機の IP に到達できること（同一ネットワークまたは
  無線機の AP モード）を確認してください。
- **レポーターが「未接続」のまま** —— 設定でコールサインを入力し、レポーターを
  有効にしてください。局一覧タブに具体的な理由が表示されます。

## 権限について

| 権限 | 用途 |
|---|---|
| マイク（`RECORD_AUDIO`） | USB／マイクからの受信音声キャプチャ、送信時のマイク |
| インターネット／ネットワーク状態 | FreeDV Reporter（qso.freedv.org）、IC-705 Wi-Fi、TCP rigctld |
| 位置情報（精密／おおよそ、任意） | Reporter 用の Maidenhead グリッドを自動計算 |
| フォアグラウンドサービス（マイク、メディア再生） | バックグラウンドでのデコード継続 |
| USB ホスト（ハードウェア機能、任意） | USB オーディオインターフェースと CAT ケーブル |

ストレージ権限は不要です——録音はアプリ専用領域に保存され、共有シートから
エクスポートされます。

## アーキテクチャ（開発者向け）

```
RX：USB／マイク／IC-705 Wi-Fi（48 kHz）
     → Oboe キャプチャ
     → ポリフェーズ FIR デシメーション（→ 8 kHz）
     → RADE V1 OFDM 復調（+ EOO コールサインデコード）
     → FARGAN ニューラルボコーダー（→ 16 kHz 音声）
     → Oboe 再生（+ WAV 録音）

TX：マイク（48 kHz）
     → 特徴抽出 → RADE OFDM 変調（8 kHz）
     → ポリフェーズ補間（→ 48 kHz）
     → USB オーディオ／IC-705 Wi-Fi → リグ（CAT で PTT 制御）
```

| レイヤー | 場所 | 説明 |
|---|---|---|
| UI | `ui/` — Jetpack Compose + Material 3 | 受信機、リグ、局一覧、マップ（osmdroid）、ログ、設定 |
| ViewModel | `TransceiverViewModel` | サービスにバインドし `StateFlow<ServiceState>` を公開 |
| サービス | `service/AudioService` | フォアグラウンドサービス（マイク + メディア再生タイプ）。セッション管理、信号スナップショット、録音 |
| JNI ブリッジ | `AudioBridge`、`RADEWrapper` | Oboe エンジン制御／RADE + FARGAN 処理 |
| ネイティブ | `app/src/main/cpp/` | `audio_engine.cpp`（Oboe ストリーム、デシメーション、フレーム分配）、`rade_jni.cpp`、`radae/`（RADE モデム、ユニティビルド）、`opus/`（FARGAN）、`eoo/`（コールサインコーデック） |
| リグ制御 | `network/`、`usb/` | 内蔵 Hamlib 4.5.5 `rigctld`（arm64）+ ネイティブ USB シリアル→pty ブリッジ。Icom RS-BA1 UDP クライアントは Kotlin 実装 |
| データ | `data/` | 生 SQLite（Room 不使用）：受信セッション、信号スナップショット、同期イベント、コールサインイベント |
| Reporter | `network/FreeDVReporter` | OkHttp による Socket.IO v4 over WebSocket |

### ソースからのビルド

```bash
git clone https://github.com/pepefrog1234/RADE_decode_Android.git
cd RADE_decode_Android
./gradlew assembleDebug          # デバッグ APK のビルド
./gradlew testDebugUnitTest      # ユニットテストの実行
```

- Android Studio（AGP 9.1／Kotlin 2.2.10）、JDK 17 以上
- NDK と CMake 3.22.1 は Gradle ビルドが自動的に処理——ネイティブの個別ビルドは
  不要
- 初回のネイティブビルド時に CMake FetchContent が Opus 1.9.0 と Oboe 1.9.0 を
  ダウンロードします（初回のみネットワーク必須）
- 成果物は **arm64-v8a のみ**——実機または arm64 エミュレーターイメージで
  テストしてください
