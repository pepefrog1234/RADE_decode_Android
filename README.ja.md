[English](README.md) | [繁體中文](README.zh-TW.md) | [简体中文](README.zh-CN.md) | **日本語**

**RADE_decode** は、Android スマートフォンやタブレットを、HF アマチュア無線用の完全な
**FreeDV RADE** デジタル音声局に変えるアプリです。RADE（Radio Autoencoder）波形を
リアルタイムで受信**および送信**でき、ニューラルボコーダーを含むすべての処理が端末上で
完結します。PC の FreeDV（freedv-gui 2.x）で RADE V1 を運用している局と交信できます。

USB ケーブル 1 本でスマートフォンを SSB トランシーバーにつなぐだけで使えます。ケーブル
なしでも運用できます。Icom 無線機のネットワークサーバーに Wi-Fi で接続する、LAN 上の
**Hermes-Lite 2** に直接接続する（スマートフォンが SDR ホストになります）、VBAN 音声で
PC の Thetis につなぐ、のいずれかです。リグ制御、FreeDV Reporter への報告、リアルタイムの
局一覧とマップ、受信ログを備えています。

> このページは **v1.6.37** の内容です。各バージョンの変更点は
> [リリースノート](docs/release-notes/)をご覧ください。

## RADE とは？

[RADE](https://github.com/drowe67/radae)（Radio Autoencoder）は、David Rowe 氏と
[FreeDV](https://freedv.org) プロジェクトが開発した機械学習ベースのデジタル音声
モードです。従来の「音声コーデック + FEC + モデム」という構成ではなく、ニューラル
ネットワークが音声を直接 OFDM シンボルへ変換・復元し、音声は Opus プロジェクトの
**FARGAN** ニューラルボコーダーが合成します。従来の HF デジタル音声モードをはるかに
超える音質で、アナログ SSB では聞き取りが難しい低 SNR でも明瞭に復調できます。

本アプリは、FreeDV プロジェクトの C 実装（[rade_c](https://github.com/freedv/rade_c)）
を使い、信号チェーン全体をスマートフォン上でネイティブ実行します：

- **モデム：** RADE V1 OFDM、30 キャリア、8 kHz で処理します。FreeDV Reporter には
  モード `RADEV1` と表示されます。
- **ボコーダー：** FARGAN、16 kHz、CPU で動作します。インターネット接続も GPU も
  不要です。
- **コールサイン：** 各送信（オーバー）の終わりに、EOO（End-Of-Over）フレームが局の
  コールサインを運びます。
- **RADE V2（実験的）：** 設定で新しい波形に切り替えられます。V1 と V2 の局は互いに
  聞こえず、V2 はコールサインを運びません。通常の運用ではオフのままにしてください。

## 主な機能

**受信**
- 48 kHz の音声ソースから RADE 信号をリアルタイムでデコード：リグ内蔵の USB サウンド
  カード、USB オーディオインターフェース、下記のネットワーク接続モード、または内蔵マイク
- キャリアマーカー付きのスペクトラムとウォーターフォール、SNR、周波数オフセット、
  3 段階の同期表示（`サーチ中 → 候補 → 同期済み`）
- デコードしたコールサインを画面と通知に表示
- **アナログ受信：** チャンネルの生の音声を聞いて、送信前に周波数が空いているかを確認
- バックグラウンドでもデコードを継続。画面を消しても、他のアプリを使っていても
  止まりません
- デコード音声はスマートフォンのスピーカー、有線／USB オーディオ、Bluetooth の
  ヘッドセットやスピーカー（**LE Audio（LC3）** を含む）で再生。出力デバイスの指定と
  テストが可能
- 同期した受信はすべて WAV ファイルに録音され、アプリ内で再生・共有が可能

**送信**
- マイク → RADE 波形 → リグ。コールサインは EOO フレームで送出
- **送信**をタップして送受信を切り替えるか、**押し続けて送信**を使用。局一覧タブと
  Map タブにも送信ボタンがあり、話しながら誰に届いているかを確認可能
- CAT による PTT 制御：無線機自身の送受信状態を読み返し、届かなかった key-on を再送。
  CAT のないインターフェースは RTS 線で PTT をかけられ、それ以外はリグの VOX を使用
- 内蔵マイク、USB／有線マイク、または（実験的）Bluetooth マイク。ゲイン調整可能。
  送信中にマイクが途切れると、アプリは PTT を戻して受信に復帰
- 送信レベルの調整機能と、UI 上の ALC 調整ガイド

**無線機との接続**（リグタブ）
- **シリアル（ローカル）：** USB CAT ケーブルと内蔵の **Hamlib 4.7.2** `rigctld`。
  180 機種以上に対応、PC 不要
- **TCP（rigctld）：** ネットワーク上の rigctld 互換サーバーに接続。Thetis、piHPSDR、
  SparkSDR、Quisk の CAT サーバー向けに **Hermes-Lite 2** プロファイルを用意
- **Wi-Fi（IC-705）：** Icom 独自のネットワークプロトコル。CAT と音声の両方が Wi-Fi
  経由で、VPN を通せば LTE でも運用可能（IC-705 と IC-7300MK2 で使用実績あり）
- **HL2（LAN）：** Hermes-Lite 2 に **openHPSDR（プロトコル 1）** で直接接続。
  スマートフォンが SDR ホストになり、PA スイッチ、LNA ゲイン、N2ADR フィルターの
  自動選択、実験的な PureSignal に対応
- **Thetis (VBAN)：** PC の Voicemeeter と Wi-Fi 経由で音声をやり取り。無線機の制御は
  Thetis のままで、PureSignal もそのまま使用可能
- 周波数、モード、PTT、S メーターをリアルタイム表示。周波数入力時はサイドバンドと
  データモードを自動選択。リグ未接続時は、FreeDV Reporter 用の周波数を手動で設定可能

**FreeDV Reporter**
- [qso.freedv.org](https://qso.freedv.org) と常時接続：受信レポート（コールサインと
  SNR）、送信状態、周波数、自由記述のステータスメッセージを送信
- **局一覧**タブ：オンラインの全局を表示。バンド（160 m – VHF+）で絞り込み、周波数・
  コールサイン・更新順で並べ替え。各行に、その局が送信中か、何を受信しているかを表示
- **Map** タブ：OpenStreetMap の世界地図に、送信中／受信中／待機中の局と大圏コースの
  信号パスを表示（コールサインをデコードできたパスは赤から緑、同じ周波数から推定した
  パスは青の破線）。各パスに SNR バッジ付き
- Maidenhead グリッドスクエアは GPS から取得、または手入力

**その他**
- 受信ログ：セッションごとに SNR 推移グラフ、同期イベントのタイムライン、デコードした
  コールサイン、信号統計を保存
- **省電力モード**：低スペック端末向け。スペクトラム、ウォーターフォール、FFT を止めて、
  CPU をデコーダーに回します
- 「電池の最適化」設定アシスタント。メーカー別の手順付き（Samsung、Xiaomi、Huawei、
  OPPO、vivo、ASUS、Sony）
- 不具合報告用に、CAT ログと音声ログをアプリ内で取得可能
- UI は English、繁體中文、简体中文、日本語に対応

## 動作要件

| | 最低要件 |
|---|---|
| Android | 8.0（API 26）以上 |
| CPU | 64 ビット ARM（**arm64-v8a のみ**。x86 版と 32 ビット版はありません） |
| 性能 | FARGAN ニューラルボコーダーは CPU で動作します。ミドルレンジの端末で十分です。古い端末や低スペック端末では **設定 → パフォーマンス → 省電力モード** をオンにしてください。 |
| 無線機 | 任意の HF SSB トランシーバー。USB オーディオと CAT を内蔵したリグ（IC-7300、IC-705 など最近の多くの機種）ならケーブル 1 本で済みます。それ以外のリグでは、スマートフォンとリグの間に USB オーディオインターフェースやデジタルインターフェース（DigiRig など）が必要です。ネットワークサーバーを内蔵した Icom 無線機と **Hermes-Lite 2** では、オーディオインターフェースは不要です。 |
| アクセサリー | USB オーディオと USB シリアルには USB-OTG アダプターが必要です。ネットワーク接続モードでは何も要りません。 |

> 受信だけならリグとの接続は不要です。マイクから音を入れる（音響カップリング）か、
> USB サウンドカードをつなぐだけで聞けます。

## インストール

1. [最新のリリース](https://github.com/pepefrog1234/RADE_decode_Android/releases/latest)
   から **`app-release.apk`** をダウンロードします。
2. Android に確認されたら、この提供元からのインストールを許可して APK をインストール
   します。
3. 最初に**開始**を押したとき、マイクの権限を許可してください。Android 12 以降では
   「付近のデバイス」の権限も求められます。Bluetooth オーディオに必要なもので、
   許可しなくても使えます。
4. 「電池の最適化」ダイアログの案内に従って設定すると、バックグラウンドでもデコードが
   続きます。

Google Play では配信していません。更新は GitHub のリリースとして公開します。

**アップデート。** v1.6.21 以降のリリースはすべて同じ鍵で署名されているので、新しい
APK を上書きインストールでき、データも残ります。次の 2 つの場合は先にアンインストールが
必要で、アンインストールするとアプリの録音、ログ、設定は消えます：

- v1.6.20 以前から更新する場合（これらは別の鍵で署名された debug ビルドでした）
- 古いバージョンに戻す場合

残したい録音は、アンインストールの前に共有して保存してください。詳しくは
[署名とバックアップのガイド（繁體中文）](docs/signing/README.zh-TW.md)をご覧ください。

## 無線機との接続

**リグ**タブを開き、スマートフォンから無線機への接続方法を選びます。次の表は、構成ごとに
音声が何を通るか、何が送信をかけるかを示します。

| 構成 | 音声 | 制御と PTT | リグタブの接続モード |
|---|---|---|---|
| USB オーディオと CAT がケーブル 1 本のリグ | USB | Hamlib（同じケーブル） | [シリアル（ローカル）](#serial-local) |
| USB オーディオインターフェースと CAT ケーブル | USB | Hamlib（CAT ケーブル） | [シリアル（ローカル）](#serial-local) |
| RTS でリグをキーイングする、CAT のないインターフェース | USB | RTS 線 | [シリアル（ローカル）](#serial-local)で **RTS PTT** をオン |
| 制御用のケーブルなし | USB またはマイク | リグの VOX、または手動 | — |
| rigctld を提供する PC または SDR ソフト | Android のオーディオデバイス | TCP | [TCP（rigctld）](#tcp-rigctld) |
| ネットワークサーバー内蔵の Icom 無線機 | ネットワーク | ネットワーク | [Wi-Fi（IC-705）](#icom-network) |
| Hermes-Lite 2 | ネットワーク（I/Q） | ネットワーク | [HL2（LAN）](#hl2-lan) |
| PC 上の Thetis と Voicemeeter | VBAN（Wi-Fi 経由） | Thetis の CAT サーバー、または VOX | [Thetis (VBAN)](#thetis-vban) |

リグを接続すると、周波数、モード、S メーターがリアルタイムで表示され、周波数の入力欄が
使えます。kHz 単位で周波数を入力して**設定**をタップすると、アプリがリグの周波数を合わせ、
サイドバンドとデータモードを選びます（10 MHz 未満は LSB／PKTLSB、以上は USB／PKTUSB。
データモードのないリグでは通常の USB／LSB）。リグを接続していないときは、**設定**を押すと
その値が手動の周波数として保存され、FreeDV Reporter にはその周波数が表示されます。

アプリ内蔵の CAT デーモンは、スマートフォン自身（127.0.0.1）からの接続だけを受け付けます。
ネットワーク上の他の機器からは接続できません。

<a id="serial-local"></a>
### シリアル（ローカル）— USB CAT ケーブル

本物の Hamlib 4.7.2 `rigctld`（arm64）をアプリに内蔵してスマートフォン上で実行し、
ネイティブの pty ドライバーで USB ケーブルとブリッジします。

1. CAT ケーブルを接続します。CDC-ACM、CP210x、FTDI、Prolific、CH340／CH341 チップに
   対応しています。Xiegu X6100 のような複合デバイスでは、各ポートが個別に表示されます。
2. **メーカー**と**機種**を選び（180 種類以上の Hamlib モデルを名前または Hamlib ID で
   検索できます）、**ボーレート**を設定します。Icom 機では必要に応じて **CI-V**
   アドレス（16 進数。空欄なら自動）を指定します。
3. **DTR／RTS：** DTR は既定でオン、RTS はオフです。*CAT ケーブルが RTS を PTT に配線
   している場合は、RTS をオフのままにしてください*。オンにすると、接続した瞬間にリグが
   送信状態になることがあります。
4. **接続**をタップし、USB の権限を許可します。

**RTS PTT。** RTS 線でリグをキーイングする、CAT のないインターフェースでは、
**RTS PTT（送信時に RTS で PTT）** をオンにし、上の RTS スイッチはオフのままにします。
送信を押すとアプリが RTS をオンにし、コールサインを送り終えてそのオーバーが終わってから
戻します。

Xiegu 機（G90、X6100、X6200、X5105、X108G）には短い CI-V タイムアウトが自動的に
適用され、PTT の反応が遅れません。

<a id="tcp-rigctld"></a>
### TCP（rigctld）— ネットワーク上のサーバー

`rigctld` 互換の TCP サーバー（既定のポートは 4532）に接続します。`rigctld` を実行
している PC や、同じプロトコルを提供する SDR ソフトが対象です。このモードでは、音声は
Android のオーディオデバイスを通ります。

**Hermes-Lite 2** プロファイルは、無線機を動かしている SDR ソフトの CAT サーバーに
接続します。**Thetis**（TCP/IP CAT サーバー）、**piHPSDR**（RigCtl ポート、既定は
19090）、**Spark/Quisk**（rigctld プロトコルを使う SparkSDR と Quisk）から選べます。
PC をまったく使わずに Hermes-Lite 2 を運用する場合は、[HL2（LAN）](#hl2-lan)を
使ってください。

<a id="icom-network"></a>
### Wi-Fi（IC-705）— Icom のネットワーク制御

無線機内蔵のネットワークサーバー（Icom の RS-BA1 プロトコル、UDP ポート 50001〜50003）
を使った完全ワイヤレス運用です。IC-705 と IC-7300MK2 で使われています。

1. 無線機のネットワーク設定で **Network Control**（ネットワーク制御）をオンにし、
   ネットワークユーザー名とパスワードを設定します。
2. スマートフォンを同じネットワーク（または無線機自身のアクセスポイント）に接続し、
   無線機の IP アドレス、ユーザー名、パスワードを入力して**接続**をタップします。
3. CAT 制御と送受信音声の両方がネットワーク経由になり、「音声 (Wi-Fi)」の表示が
   *接続済み*になります。USB ケーブルもオーディオインターフェースも不要です。

リグタブのオプションは、次回の接続から有効になります：

- **音声バッファ（ネットワーク遅延）：** 150 ms が無線機の既定値です。200 ms または
  300 ms にすると、LTE や VPN のジッターを吸収できます。
- **送信音声 16 kHz（実験的）：** 上りのデータ量が 3 分の 1 になります。LTE の上りが
  詰まるときに試す価値があります。
- **受信音声 16 kHz（実験的）：** 無線機に 16 kHz の受信音声を要求します。音が出ない
  場合はオフに戻して再接続してください。

**外出先から。** VPN で無線機のあるネットワークに入れば、LTE 経由でも運用できます。
無線機にはデフォルトゲートウェイの設定が必要で、VPN は、スマートフォンに無線機の
サブネット内のアドレスを割り当てるか、NAT でそのサブネットに変換する必要があります。
回線が切れた場合、アプリは自動的に再接続して受信に戻ります。

<a id="hl2-lan"></a>
### HL2（LAN）— Hermes-Lite 2、PC 不要

LAN 上の Hermes-Lite 2 に **openHPSDR（プロトコル 1）** で直接接続します。
スマートフォンが SDR ホストになります：

1. HL2 をスマートフォンと同じ LAN に接続します（ルーターまたはアクセスポイントに有線で
   接続）。
2. **リグ**タブで **HL2（LAN）** を選びます。**ホスト**を空欄にするとブロードキャストで
   自動検出します。無線機の IP アドレスを入力しても構いません。その後、**接続**を
   タップします。
3. 周波数と PTT はアプリから制御します。48 kHz の I/Q ストリームが UDP ポート 1024 で
   双方向に流れ、SSB の変調と復調はアプリ自身が行います。

リグタブの操作項目：

- **送信ドライブ**（0〜255、既定は 128）。0 にすると、キーイングしても出力は出ません。
- **受信 LNA ゲイン**（−12〜+48 dB）。
- **PA（5 W 出力）：** 既定でオンです。オフにすると低電力の端子（約 10 mW）を使い、
  アンテナ端子は受信のままになります。トランスバーターや外部アンプと組み合わせる場合に
  使います。
- **PureSignal（実験的）：** Thetis と同じ WDSP エンジンによる適応型プリディストーション
  です。既定ではオフで、PA がオンのときに効果があります。

N2ADR フィルターボードのフィルターは、周波数に応じて自動的に選択されます。

注意事項：
- このモードでは「オーディオデバイス」の設定は**使用されません**。送受信の音声は
  ネットワークを通ります。
- 接続時に「Radio is busy」と表示される場合は、別のホスト（Thetis、Quisk、SparkSDR
  など）がすでに HL2 とストリーミングしています。そちらを終了してから再接続してください。

<a id="thetis-vban"></a>
### Thetis (VBAN) — Wi-Fi 経由で PC と音声をやり取り

PC の Thetis が無線機を動かしている局向けのモードです。スマートフォンの送受信音声は、
VBAN プロトコルで Wi-Fi を通り、PC の
[Voicemeeter](https://vb-audio.com/Voicemeeter/) とやり取りされます。Voicemeeter の
仮想ケーブルが Thetis の VAC になります。Thetis は PureSignal を含めてこれまでどおり
動作し、スマートフォンと PC の間にサウンドカードもケーブルも要りません。

1. Voicemeeter で、スマートフォンの IP アドレス宛ての**送信（Outgoing）** VBAN
   ストリーム（48 kHz、PCM 16 ビット）を設定し、送信方向には `RADE-TX` という名前の
   **受信（Incoming）**ストリームを選びます。
2. **リグ**タブで **Thetis (VBAN)** を選び、**ホスト**に PC のアドレスを、続けて
   **VBAN ポート**（既定は 6980）と、SDR ソフトの CAT サーバーの **CAT ポート**を入力
   します。CAT ポートを空欄または 0 にすると、CAT を使わずに VOX で運用します。
3. SDR ソフト（Thetis、piHPSDR、Spark/Quisk）を選び、**接続**をタップします。

PC 側の設定手順は [v1.5.62 のリリースノート](docs/release-notes/v1.5.62.md)に詳しく
書かれています。

## 受信

1. **音声を接続します。** おすすめの順：
   - *USB オーディオ：* OTG アダプターでリグまたはオーディオインターフェースを
     スマートフォンに接続し、**設定 → オーディオデバイス → 入力デバイス**で選択します。
   - *ネットワーク接続モード：* リグタブで Wi-Fi（IC-705）、HL2（LAN）、Thetis (VBAN)
     のいずれかに接続すると、受信音声はネットワーク経由で届きます。
   - *マイク：* スマートフォンをリグのスピーカーに近づけます。動作はしますが、USB
     オーディオのほうがはるかに安定します。
2. **リグを** RADE の運用がある周波数に合わせます。たとえば 20 m の FreeDV 呼出周波数
   **14.236 MHz USB** です。**局一覧**タブと [qso.freedv.org](https://qso.freedv.org)
   で、いま誰がどの周波数に出ているかを確認できます。
3. **受信機**タブを開き、**開始**を押します。
4. **入力**メーターを見ます。ピークが **−15〜−5 dBFS** 付近になるよう、リグの出力
   または**設定 → 入力ゲイン → デジタルゲイン**を調整します。
5. RADE 信号が現れると、ヘッダーが `サーチ中 → 候補 → 同期済み` と変わり、音声の再生が
   始まります。相手のオーバーが終わると、「最後に復号したコールサイン」の下に
   コールサインが表示されます。EOO フレームはそのときに送られるからです。

**アナログ受信。** 受信中に**アナログ受信**をタップすると、デコードした音声の代わりに
チャンネルの生の音声が再生されます。送信する前に、その周波数でアナログの交信が行われて
いないかを聞いて確かめられます。同期表示は動き続けます。もう一度タップすると RADE に
戻ります。

同期するたびにセッションが始まります。セッションは**ログ**タブに一覧表示され、デコード
音声は WAV ファイルとして保存されるので、あとで再生・共有できます。

## 送信

> 送信にはアマチュア無線の有効な免許が必要です。

1. **設定 → 送信コールサイン：** 自局のコールサインを入力します（最大 8 文字。英字、
   数字、`/`）。オーバーの終わりごとに EOO フレームで送出され、FreeDV Reporter でも
   必要です。
2. **設定 → オーディオデバイス → 送信出力デバイス：** リグにつながる USB オーディオ
   デバイスを選びます。ネットワーク接続モードでは不要です。送信音声はネットワークを
   通ります。
3. **開始**を押してから**送信**をタップし、マイクに向かって話します。**受信に戻る**を
   タップするとオーバーが終わります。コールサインのフレームが送出されてから PTT が
   戻ります。
4. **レベルを合わせます。** 目標は、リグの *ALC がほとんど振れない*ことです：
   - スマートフォンの**音量キー**（Android のメディア音量）と
     **設定 → 送信出力 → USB 送信レベル**で、リグの USB 音声入力へのドライブ量が
     決まります。
   - **設定 → 送信マイク → 送信マイクゲイン**は声の大きさを変えるもので、RF の
     ドライブ量は変わりません。
   - リグ側の USB 変調レベルも確認してください（IC-7300：
     `Menu → SET → Connectors → USB MOD Level`）。
   - ネットワーク接続モードでは、ドライブ量は無線機側で設定します。HL2 では
     **送信ドライブ**を使います。
5. **PTT。** **リグ**タブでリグを接続していれば、アプリが PTT を操作します。リグ制御が
   ない場合は、RTS PTT、リグの VOX、または手動で操作してください。

**押し続けて送信。** **設定 → PTT → 押し続けて送信（PTT）**をオンにすると、送信ボタンが
トランシーバーのように動作します。押している間だけ送信し、離すと受信に戻ります。

**局一覧タブと Map タブからの送信。** 受信を開始している間、この 2 つのタブでは
ナビゲーションバーの上にバーが表示され、同じ送信ボタンが使えます。ボタンの横には、
受信中は同期状態・SNR・自局の周波数が、送信中は送信時間とマイクレベルが表示されます。
押し続けて送信の場合、2 つのタブを切り替えてもボタンは押されたままです。この 2 つの
タブを離れると PTT は解除されます。

## FreeDV Reporter・局一覧・マップ

**設定 → FREEDV REPORTER → Enable Reporter** をオン（既定）にしてコールサインを設定
すると、アプリは qso.freedv.org との接続を維持します：

- デコードした内容（コールサインと SNR）を報告します。同期中は「受信中」のハートビートも
  送られるので、他の局からは自局の反応がリアルタイムで見えます。
- 送信状態と周波数を報告します。周波数は接続中のリグから取得し、リグがない場合は
  リグタブで設定した周波数になります。
- グリッドスクエアは GPS から取得する（入力欄の横の **GPS** をタップ）か、手入力します。
  空欄の場合は `UN00KN` として報告され、自局はマップに表示されません。
- 80 文字までのステータスメッセージを、自局の横に表示できます。
- コールサインを設定していない場合、アプリは接続しません。理由は局一覧タブに表示
  されます。

**局一覧**タブには、オンラインの全局がグリッド、周波数とともに並び、各局の状態として
`TX`、または受信している内容（`RX K1ABC 12 dB`）が表示されます。バンドで絞り込み、
周波数（既定。同じ周波数の局は 1 つの見出しにまとまります）、コールサイン、更新順で
並べ替えられます。**Map** タブは、これらの局を世界地図に表示します：

| マーカー／線 | 意味 |
|---|---|
| 🔴 赤マーカー | 送信中の局 |
| 🟢 緑マーカー | 受信中の局（周波数と SNR を表示） |
| ⚪ 灰色マーカー | 待機／ワッチ中 |
| 赤→緑のアーク | 確認済みのパス：受信側が送信局のコールサインをデコード |
| 青の破線アーク | 推定のパス：受信側が同じ周波数（±5 kHz）で同期 |
| SNR バッジ | パスの中間点に、報告された SNR を色分けして表示 |

## 受信ログ

**ログ**タブには、すべての受信セッションが保存されます。同期が約 2 秒途切れると
セッションは終了します。セッションをタップすると、次の内容が表示されます：

- 開始と終了の時刻、継続時間、同期率、モデムフレーム数、使用したオーディオデバイス
- **デコード音声の再生と共有**
- デコードしたすべてのコールサイン（そのときの SNR とセッション内の位置付き）
- SNR 推移グラフ、同期イベントのタイムライン、信号統計（ピーク／平均 SNR、周波数
  オフセットの範囲）

録音はアプリ専用領域に保存され、Android 標準の共有シートから共有できます。

## トラブルシューティング

- **ウォーターフォールに信号は見えるのに同期しない。** まずサイドバンド（10 MHz 以上は
  USB、未満は LSB）を、次に入力レベル（−15〜−5 dBFS）を確認してください。音声が
  大きすぎる、または小さすぎることが最も多い原因です。相手が V2 を使っている場合を除き、
  RADE V2 がオフになっていることも確認してください。
- **オレンジ色の警告「デバイスがUnprocessedモードを拒否しました」。** 端末が、選択した
  入力に音声処理（AEC／AGC）を強制的にかけており、デコードに失敗することがあります
  （例：Samsung Galaxy S24 の内蔵マイク）。USB オーディオ入力を使ってください。
- **低スペック端末で音が途切れる、ロボットのような声になる。** **省電力モード**をオンに
  してください。ボコーダー以外では、スペクトラムの描画と FFT が CPU 負荷の大半を
  占めます。
- **ヘッダーは同期済みなのに音が出ない。**
  **設定 → 受信出力 → 選択中の受信出力をテスト**を実行してください。出力先の問題
  なのか、まだ音声がデコードされていないだけなのかを切り分けられます。そのうえで、
  出力デバイスを自分で選んでください。
- **画面を消すとデコードが止まる。** 電池の最適化がサービスを止めています。電池設定の
  ダイアログ（初回起動時に表示されます）と、そこに並ぶメーカー別の手順に従って
  ください。
- **シリアルケーブルをつないだ瞬間にリグが送信状態になる。** CAT ケーブルが RTS を PTT に
  配線しています。リグタブで **RTS** をオフにしてください。
- **「CAT の PTT 応答を確認できません」。** 無線機を確認してください。切り替わって
  いれば、そのまま運用できます。アプリは再試行と状態の読み返しを続けます。送信のまま
  戻らない場合は**停止**を押してください。
- **「無線機は受信のままです」。** 無線機が送信を受け付けていません。無線機側で
  送信禁止、SWR 保護、バンドとモードを確認してください。
- **「マイク音声が途切れたため送信を停止しました」。** アプリは PTT を戻して受信に復帰
  しています。マイクと、その USB 接続を確認してください。
- **USB シリアルデバイスが見つからない。** 端末が USB-OTG に対応しているか確認し、
  **更新**をタップして、Android の USB 権限ダイアログで許可してください。
- **以前のバージョンでは動いていた CAT が動かない。** v1.6.36 で、内蔵の Hamlib が
  4.5.5 から 4.7.2 に変わりました。CAT ログを取得し、機種名を添えて issue を作成して
  ください。
- **Icom のネットワーク接続ができない。** Network Control がオンであること、ユーザー名と
  パスワードが無線機の設定と一致していること、スマートフォンから無線機の IP アドレスに
  到達できることを確認してください。VPN 経由の場合は、
  [Wi-Fi（IC-705）](#icom-network)のルーティングの説明をご覧ください。
- **Icom を LTE で使うと音が途切れる。** 音声バッファを 200 ms または 300 ms にし、
  **送信音声 16 kHz** を試してください。
- **HL2（LAN）：「Radio not found」。** ブロードキャストで検出するには、スマートフォンが
  Hermes-Lite 2 と同じ LAN、同じサブネットにある必要があります。そうでない場合は、
  **ホスト**に無線機の IP アドレスを入力してください。「Radio is busy」は、別の SDR
  ホストが接続中という意味です。
- **HL2（LAN）：リレーは動くのに RF が出ない。** リグタブの**送信ドライブ**スライダーと
  **PA** スイッチを確認してください。
- **Reporter が「未接続」と表示される。** 設定でコールサインを入力し、
  **Enable Reporter** をオンにしてください。局一覧タブに具体的な理由が表示されます。
- **原因を特定しにくい問題。** **設定 → 診断**で、アプリの直近の CAT ログと音声ログを
  端末上で取得できます（adb は不要です）。そのまま
  [GitHub の issue](https://github.com/pepefrog1234/RADE_decode_Android/issues) に
  貼り付けられます。

## 権限とネットワークの利用

| 権限 | 用途 |
|---|---|
| マイク（`RECORD_AUDIO`） | USB またはマイクからの受信音声、送信用のマイク |
| 付近のデバイス（`BLUETOOTH_CONNECT`、Android 12 以降、任意） | Bluetooth ヘッドセットと LE Audio の音声ルーティング |
| 位置情報（精密／おおよそ、任意） | Reporter 用の Maidenhead グリッドを計算 |
| インターネット／ネットワーク状態 | FreeDV Reporter、ネットワーク接続モード、地図タイル |
| フォアグラウンドサービス（マイク、メディア再生）、ウェイクロック | アプリがバックグラウンドにある間もデコードを継続 |
| USB ホスト（ハードウェア機能、任意） | USB オーディオインターフェースと CAT ケーブル |

ストレージの権限は不要です。録音はアプリ専用領域に保存され、共有シートから取り出します。

アプリが接続するのは、qso.freedv.org（Reporter が有効で、コールサインを設定している
場合）、OpenStreetMap のタイルサーバー（Map タブを開いている場合）、そしてリグタブで
設定した無線機または PC だけです。広告や解析のコードは含まれていません。

## 開発者向け

### アーキテクチャ

```
RX：USB／マイク／Icom ネットワーク／VBAN（48 kHz）   HL2：UDP 経由の I/Q（48 kHz）
     → Oboe キャプチャまたはネットワークパケット     → 複素デシメーション ÷6
     → ポリフェーズ FIR デシメーション（→ 8 kHz）    → 解析信号 USB 復調（→ 8 kHz）
     → RADE OFDM 復調（+ EOO コールサインデコード）
     → FARGAN ニューラルボコーダー（→ 16 kHz 音声）
     → Oboe 再生（+ WAV 録音）

TX：マイク（48 kHz）
     → 特徴抽出 → RADE OFDM 変調（8 kHz）
     → ポリフェーズ補間（→ 48 kHz）→ USB オーディオ／Icom ネットワーク／VBAN
       または 解析信号フィルタ + ×6 補間 → 16 ビット I/Q → UDP 経由で HL2 へ
     （PTT は CAT、RTS、または MOX）
```

| レイヤー | 場所 | 説明 |
|---|---|---|
| UI | `ui/` — Jetpack Compose + Material 3 | 受信機、リグ、局一覧、Map（osmdroid）、ログ、設定。`PttDock` は局一覧タブと Map タブの送信バー |
| ViewModel | `TransceiverViewModel` | サービスにバインドし、UI の状態を `StateFlow` で公開 |
| サービス | `service/AudioService` | フォアグラウンドサービス（マイク + メディア再生タイプ）。セッションの管理、スナップショット、録音 |
| JNI ブリッジ | `AudioBridge`、`RADEWrapper` | Oboe エンジンの制御、RADE + FARGAN の処理 |
| ネイティブ | `app/src/main/cpp/` | `audio_engine.cpp`（Oboe ストリーム、デシメーション、フレーム分配）、`rade_jni.cpp`、`radae/`（RADE モデム。[rade_c](https://github.com/freedv/rade_c) を無改変で同梱）、`opus/`（FARGAN を含む Opus を同梱）、`eoo/`（コールサインコーデック）、`wdsp_ps/`（WDSP の PureSignal エンジン） |
| リグ制御 | `network/`、`usb/` | 内蔵の Hamlib 4.7.2 `rigctld`（arm64）と、ネイティブの USB シリアル→pty ブリッジ。Icom RS-BA1、openHPSDR プロトコル 1（Hermes-Lite 2。SSB モデムはアプリ内）、VBAN の各クライアントは Kotlin 実装 |
| データ | `data/` | 生の SQLite（Room 不使用）：セッション、信号スナップショット、同期イベント、コールサインイベント |
| Reporter | `network/FreeDVReporter` | OkHttp による WebSocket 上の Socket.IO v4 |

### ソースからのビルド

```bash
git clone https://github.com/pepefrog1234/RADE_decode_Android.git
cd RADE_decode_Android
./gradlew assembleDebug          # デバッグ APK
./gradlew testDebugUnitTest      # ユニットテスト
```

- Android Studio（AGP 9.1、Kotlin 2.2.10）と JDK 21。Android Studio 付属の JBR で
  動作します
- NDK と CMake 3.22.1 は Gradle ビルドが自動的に呼び出します。ネイティブ部分を別に
  ビルドする必要はありません
- 初回のネイティブビルドでは、CMake FetchContent が Oboe 1.9.0 をダウンロードします
  （ネットワークが必要なのは初回だけです）。Opus と RADE モデムのソースはリポジトリに
  含まれています
- 成果物は **arm64-v8a のみ**です。実機または arm64 のエミュレーターイメージでテスト
  してください
- `assembleRelease` にはリリース署名用の鍵が必要で、鍵がないと失敗します。
  [署名ガイド（繁體中文）](docs/signing/README.zh-TW.md)をご覧ください

  これらはスキップされます。同梱バイナリのビルドとパッチの方法は
  [tools/hamlib/README.md](tools/hamlib/README.md) にあります。
- `./gradlew connectedDebugAndroidTest` は、接続した端末でインストルメンテーション
  テストを実行します。
- `radae/` または `opus/` を更新したら、`tools/radecheck` のホスト側ループバック
  チェックを実行してください。
- 同梱のモデムと `rigctld` のメンテナンス上の注意は、[CLAUDE.md](CLAUDE.md) に
  まとめてあります。
